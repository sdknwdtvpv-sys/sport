## 0. 一句话结论

**问题不是"这个 App 没有设计系统"，而是"设计系统全都在，但被加法用坏了"**：
三套"今天练什么"、四套"坚持"、六只同款方块、训练屏一屏十处橙色 / 首页六处 —— 于是每一块单看都不差，
合在一起没有主次。

这一版只做三件事：

1. **首页只回答一次"今天练什么"**：今日训练卡（表格化 + 显式编辑 + 开始按钮一体）·
   最近一次（一行）· 周节奏（一条）。
2. **训练屏把纵向空间还给组表**：已完成 / 当前组 / 上次对照 / 目标，一行一组；
   「动作要领」收成一行可展开；说教文案全部删除；1 次点击 = 1 组不变。
3. **统计统一收口到「进步」**：周期切换 + 累计趋势（本周 vs 上周同期）+ 连续 / 本周摘要 +
   部位分布 + PR + 最近训练；首页与「我」不再各养一份统计。

**A 与 B 分别落在哪**（避免"方向"只有形容词）：

| 方向 | 这一版里的具体决定 |
| --- | --- |
| **A · 紧凑训练工具** | 动作行表格化（4 列）· 组表一行一组（组 / 重量 / 次数 / 上次 / 状态）· 待做组降透明度而不是留白 · 「动作要领」收成一行 · 操作入口显式化（编辑 / 改重量 / 换动作）· 首页只留三块 · 正文量压到最少 |
| **B · Apple Fitness 式质感** | 暖黑 5 层 + 顶部 1px 高光 + 细线分节 · 30pt 大标题与 34pt 大数字 · 数字 tabular-nums · 一只图表卡（渐变面积 + 上周虚线）· 浮起玻璃底栏 · 克制的 12px 圆角 · 橙只在一处出现，其余用暖白 / 灰阶 |

| # | 现象（v1.71.1 真机 / 截图） | 这一版怎么回应 |

### 1.3 截图里额外发现的三处（不在用户口述里，但值得修）

1. **今日卡标题与动作不一致（逻辑 bug）**：用户 v1.71.1 截图上写着「今天练 **下肢** · 健身房」，
   下面四行却是杠铃卧推 / 哑铃卧推 / 上斜哑铃卧推 / 引体向上 —— 全是上肢。
   这比"丑"更严重：**标题与内容是两套数据**。建议核 `main.dart` 的 `_todayPlan` 标题来源
   与 `today_planner` 的日类型是否同源，并加一条 widget 测试：
   **标题里的部位集合必须覆盖动作行的主肌群**（或至少不出现互斥）。
   本稿的数据是自洽的：今天下肢 → 腿举 / 深蹲 / 罗马尼亚硬拉 / 保加利亚分腿蹲。
2. **"这周胸 4 次、背、腿、肩、手臂、核心还是 0 次"**：这句话同时犯了三个错 ——
   ① 把"组数"说成"次数"；② "还是 0 次"是责备口吻；③ 它出现在首页，抢「进步」的活。
   新稿：部位分布进「进步」，单位是**组**，用 12–20 组的循证刻度呈现，不做评价句。
3. **「本期没练」的对比文案**：`08-progress.png` 里四格统计的下方写着「本期没练」，
   但当前周期明明有 640 kg / 1 次。它想说的是"上一周期没数据、所以没有对比"，
   读起来却像"你本期没练"。新稿口径：**没有可比的上期数据时，直接不显示 delta**；
   有数据才写「较上周同期 +18%」。不编百分比，也不摆一句像责备的占位话。

## 2. 三屏信息架构（留什么 / 砍什么 / 搬去哪）

### 2.1 首页（开练）—— 只留三块

```
今天  11 月 7 日 · 周六
┌──────────────────────────────┐
│ 今日训练              [✎ 编辑] │
│ 下肢 · 健身房                  │
│ 4 个动作 · 12 组 · 约 45 分钟  │
│ #  动作              组×次  重量 │
│ 01 腿举              3×12  140 │
│ 02 杠铃深蹲           4×8  102.5│
│ 03 罗马尼亚硬拉        3×10   80 │
│ 04 保加利亚分腿蹲      2×10   20 │
│ ┌──────────────────────────┐ │
│ │      ▶ 开始训练            │ │  ← 与卡一体
│ └──────────────────────────┘ │
└──────────────────────────────┘
最近一次   11/6 周五 · 上肢 · 4 个动作   5.2 吨  ›
──────────────────────────────
本周节奏   一 二 三 四 五 六 日  已练 3 天
                     ✓ ✓ ✓ ◉
```

**留下**

- **今日训练卡**：卡头（今日训练 / 部位 · 场景 / 动作数 · 组数 · 时长）+ **显式「编辑」**；
  动作行**表格化**（`#` / 动作 / 组 × 次 / 重量）；**开始按钮与卡一体**。
  数字用 tabular-nums，单位降一级，动作名 16–22pt。
- **最近一次**：一行，日期 + 部位 + 动作数 + 吨位，右箭头进详情。不做卡片、不做列表。
- **周节奏**：一条，7 个圆点 + 星期；已练=实心勾，今天=橙描边 + 内点，未练=描边。
  只有一个"已练 3 天"的小事实，**不出现容量 / 连续 / PR / 部位分布**。

**砍掉 / 搬走**

| 原来首页的东西 | 去向 | 理由 |
| --- | --- | --- |
| 「已连续打卡 N 天 · 本周已练 N 次」一行 | 「进步」hero 的 facts 区 | 连续是"统计"，不是"今天要做的事"；首页只留周节奏的视觉 |
| 打卡卡 + 本周挑战 | 「进步」；成就细节进「我 → 成就」 | 2026-10-10 已收成一行，这次再进一步：首页不出现第二条进度 |
| 「换一批」「计划 ›」两个卡头入口 | 合并进「编辑」；「计划」只在编辑页 + 我 → 训练计划 | 一次只回答一个"今天练什么" |
| 长按调整顺序 / 换动作 / 删掉 说明行 | 删除；「编辑」进入编辑态后才有拖动把手 | 操作说明不是正文 |
| 动作库 / 记录体重 / 5 分钟活动 三格 | 动作库 → 训练屏「换动作」搜索；记录体重 → 我 → 身体数据；5 分钟活动 → 进步/我（待拍板） | 都是低频二级动作，不该占首页拇指区 |
| 「这周胸 4 次…还是 0 次」一行 | 「进步 → 部位分布」 | 单位错、语气责备、且是统计 |
| 最近训练列表 | 首页只留一行；完整列表在「进步 → 最近训练」 | 首页不需要第二条时间线 |
| 「我上周练了 N 次」 | 删除 | 与周节奏/进步重复 |
| 成就磁贴 | 我 → 成就 | 收藏册不是今天要做的事 |

**空态**：今日没有安排时，卡照常显示，标题写「今天还没有安排」，副标题
「从模板载入 / 选一个动作开始」，「编辑」变成「去安排」；不出现"暂无数据"。
没有任何训练记录时，"最近一次"整行**不渲染**（不摆空行），周节奏仍显示 7 个空点。
（现有 `docs/screens.md` S1 的规则"计划为空时卡片照常显示"继续成立。）

**空间分配（390×844，实测）**

| 区域 | 高度 | 内容 |
| --- | --- | --- |
| 状态栏 | 46 | 系统 |
| 顶栏 + 4 段动作进度 | 64 | 返回 / 动作名 / 动作 2 / 4 / 换动作 |
| 动作要领（收起） | 40 | 一行，点击展开；没有说明的动作整行不渲染 |
| 对照带 | 64 | 上次 / 最佳 / 目标，细线上下夹住 |
| 本次 + 组表 | ≈ 296 | 表头 24 + 4 行 × 58 + 内边距 |
| 休息条 | 46 | 时间 + 百分比细进度 + −15 / +15 / 跳过 |
| 底部操作区 | 214 | 第 N 组 + 改重量 + 88pt 记录键 + 上一个/下一个 |

**与现有 spec 的一处有意偏离（需要确认）**

1. **未完成组要不要显示**：`docs/screens.md:228` 写「组列表只显示已完成的，未完成的不占位
   （避免计划感压迫）」。这一版**显示全部 4 行**（当前 + 待做），因为 A 的结构要的是
   "看一眼就知道还剩几组、每组目标多少"，而不是藏在脑子里数。代价是引入"计划感"；
   缓解办法：待做行降到 42% 透明度、不用强调色、不加分割线；当前行只占 1 行。
   这是这一版**最值得用户拍板的一条**（见 §6）。

> **口径确认（不是偏离）**：现有 spec 已把「动作 x/4」放顶栏、「第 N 组」放按钮上方；
> 本稿保持，不合并成一个 x/y —— 两个数字含义不同，合在一起必读错。

**不变**

- **1 次点击 = 1 组**；大按钮上写的是**将要写入的值**（`102.5 kg × 8`），不是"记录"。
- 主按钮在屏幕下 1/3，高 88；休息条是它的状态延续（橙），不是第二个主操作。
- 组数达标后不禁用，继续点仍然记录（计划是建议不是牢笼）。
- 撤销：长按已完成行仍是快捷方式；界面上「改重量」是可见胶囊（原 2026-10-10 决定保留）。
- **训练屏不画底栏**：`docs/interaction-spec.md` §1 的唯一例外 —— 训练态是沉浸态，
  切 Tab 会让用户离开当前动作。其他两屏都画（见静帧）。

**留下 / 为什么**

| 区块 | 为什么留 | 取舍 |
| --- | --- | --- |
| 周期切换（周 / 月 / 年） | 一个控件统管全页，用户不用猜"这个数字是什么周期" | 现有是"趋势卡里的分段只换曲线、统计带不跟"；新稿统一 |
| 容量大数字 + 较上周同期 | 一屏唯一的"大数字"；回答"练得怎么样" | 比较口径写「同期」而不是整周（周六不能拿半周比整周） |
| 连续天数 / 本周次数 / 总时长 | 用户点名的"连续 / 本周摘要" | 一行三格，数字 17pt，标签 10pt，不做进度条 |
| 累计趋势 | 容量趋势是唯一需要"图形底衬"的内容 | 只保留**这一只卡片**；本周实线 + 上周虚线；周累计比单日柱状更能看出"持续" |
| 部位分布 | 12–20 组循证区间是产品差异化；"这周腿 0 组"是最该被看见的一句话 | 用"组"不是"次数"；刻度线标 12；不写"还是 0" |
| 个人纪录 | 破纪录是训练者最想看的正反馈 | 只显示本周期 PR（最多 2–3 行）；全部 PR 在「全部数据」 |
| 最近训练 | 一屏收口的最后一行，可进详情 | 一行，不列列表 |

**移出 / 移入**

| 内容 | 处理 |
| --- | --- |
| 首页的「连续 / 本周」 | 移入 hero facts |
| 「我」的「训练统计两张卡」（连续天数 / 累计容量） | 移入「进步」；「我」只剩等级 + 成就 + 身体数据 + 计划 + 设置 |
| 「全部数据」 | 右上角文字链接保持；它是二级页，不是第 4 个 Tab |
| 体重 | `docs/interaction-spec.md:230` 曾把体重算进「进步」第 4 块；新稿不再把体重塞进这一屏（它属于身体数据），否则一屏又变六块 |
| 「进阶分析 / Ultra」 | 不进这一屏；继续从「全部数据」进（避免免费用户被锁入口） |

**与现有 spec 的冲突**：`docs/interaction-spec.md` §11 第 5 条写「进步页增加第 4 块内容（一条线 +
PR 墙 + 体重，封顶）」。新稿是 **6 个分区**（周期切换 / hero / 趋势 / 部位 / PR / 最近），
比"封顶 3 块"多。理由：那一条是 2026-09 在"6 只方块"时代的克制令，真正要防的是
**同权重方块堆叠**；新稿用**分区 + 细线 + 一只图表卡**解决，而不是靠删信息。
若用户要严守旧契约，最小删法是砍掉「最近训练」一行（PR 与部位保留）。

**底栏材质**：静帧按现在 iOS 的浮起玻璃胶囊画（与用户 v1.71.1 真机一致）。

Android 与静帧保持一致。这一条标为待拍板（§6-2）。

### 3.2 计划：一个心智，两个视图

**问题**：现在"今天练什么"有三个答案来源 ——「换一批」（规则引擎重新生成）、
「计划 ›」（模板与历史）、以及长按手改。用户看到三个入口，自然以为是三件事。

**新模型**：

```
今日安排（唯一的心智）
├── 首页今日训练卡：只读 + 开始训练
├── 编辑（显式按钮）：换动作 / 拖动排序 / 删除 / 从模板载入 / 重新安排
│   └── 「重新安排」= 原「换一批」，是编辑页里的一个动作，不是卡头第二个入口
└── 我 → 训练计划：模板库 / 本周 / 历史（与编辑页同一份数据）
```

三条规矩：

1. **一次只回答一个"今天练什么"**：首页卡头只有「编辑」一个入口，没有「换一批 / 计划」并排。
2. **自动生成仍是默认，但不做黑盒**：编辑页里「重新安排」要显示理由（规则引擎本来就会给
   "上次 3 组全部达标，线性加重 +2.5kg"），理由放在编辑页，不占首页。
3. **计划不是前提**：没定计划也能点开始（沿用 `PRODUCT.md` §2 第 2 条）；
   没定计划时首页卡显示「今天还没有安排」，按钮仍可开始（进入动作选择）。

### 3.3 统计：全部归「进步」

| 数字 | 现在出现在 | 新位置 | 理由 |
| --- | --- | --- | --- |
| 连续天数 | 首页一行 +「我」一行 | 进步 hero facts | 事实，不是进度；只留一处 |
| 本周训练次数 | 首页一行 +「我」 | 进步 hero facts | 同上 |
| 容量（周 / 月 / 年） | 进步 +「我」累计容量 | 进步 hero + 趋势 | 同一口径只留一处 |
| 本周组数 | 进步统计带 | 部位分布求和（不单列） | 组数在部位分布里已经能加出来；少一个数字 |
| 部位分布 | 首页一行灰字 | 进步 | 单位改"组"，加 12–20 刻度 |
| PR | 进步 + 完成页 | 进步（本周期）+ 完成页（当场） | 两处语义不同：进步是"历史最好"，完成页是"刚刚破的" |
| 等级 / 成就 | 「我」 | 「我」（不变） | 唯一进度条 + 收藏册 |
| 训练统计两张卡 | 「我」 | 删除 | 与进步重复 |

**「我」的最终结构（本稿未画，但必须定）**：
身份块 → 我的进度（等级，唯一一条进度条）→ 成就（`已解锁 N / M`）→ 身体数据 →
训练计划 → 数据与备份 → 设置（顶栏齿轮）→ 版本。
不再有"训练统计"与"连续天数"。

### 3.4 编辑可发现性 / 手势

- **显式入口**：卡头「编辑」按钮（铅笔 + 文字，44×44 触区），不靠长按。
- 进入编辑态后才出现拖动把手与删除按钮；把手在行的右侧，**不写"长按拖动"说明**。
- 长按整卡仍可作为快捷方式进入编辑（不写进文案），但**不是唯一路径**。
- 训练屏「改重量」保持可见胶囊；长按大按钮仍是快捷方式（spec 的 500ms）。
- 撤销仍是长按已完成行（spec §7），界面上不写"长按可撤销"；若担心发现性，
  在训练屏表头放一个不抢眼的「撤销」文字按钮（本轮未画，列为后续）。

### 3.5 训练屏的空间账（为什么这样排）

- **上半屏不再留黑**：对照带 + 四行组表把纵向吃掉；组表是训练中真正会来回看的东西。
- **主按钮回到下 1/3**：88pt，拇指区；上方只放"第 N 组 / 改重量"一行，不堆信息。
- **休息条是状态，不是第二块 UI**：一条 3px 进度 + 时间 + 百分比，位于按钮上方；
  休息时按钮上的值就是下一组，二者是同一件事的两种表达。
- **要领收成一行**：默认 12pt / 一行省略；点开才显示全文。
  ⚠️ 现有 `docs/screens.md:274-281` 规定"没有说明的动作什么都不摆"——新稿保持。
- **删掉的文案**：`第一次练这个动作，先从这个重量开始`、`点大按钮记录一组`、
  `长按某一行可撤销`、`长按调整顺序 / 换动作 / 删掉`。理由：这些都是操作说明或说教，
  用可见控件与默认值替代，而不是用字解释字。

### 3.6 文案口径（每屏正文不超过必要量）

| 场景 | 旧 | 新 |
| --- | --- | --- |
| 首页主按钮 | 开始今天的训练 | **开始训练**（点后会发生什么） |
| 首页卡头 | 换一批 · 计划 › | **编辑**（唯一入口） |
| 首页卡内说明 | 长按调整顺序 / 换动作 / 删掉 | 删除（编辑态里用控件表达） |
| 首页连续 | 已连续打卡 1 天 · 本周已练 1 次 | 删除（进步 hero） |
| 训练屏要领 | 四行段落 + "看完整说明 ›" | 一行「动作要领」+ 省略号；点开全文 |
| 训练屏提示 | 第一次练这个动作，先从这个重量开始 | 删除（对照带"上次/目标"已经回答） |
| 训练屏底部 | 点大按钮记录一组 | 删除（按钮上就是值） |
| 部位分布 | 这周胸 4 次、…还是 0 次 | 胸 12 组（单位正确，不做评价） |
| 进步 hero | 本期没练 | 较上周同期 +18% / 无数据时留空不编 |

**三条文案规则**（延伸 `docs/copy.md` 的五条判据）：

1. **按钮上写将要发生的值 / 动词**，不写抽象名词（"记录"）。
2. **操作说明不进正文**：能做成可见控件就不写成字；必须写时放编辑态或帮助层。
   ⚠️ `docs/copy.md` 把「点大按钮记录一组 · 长按可以改重量」列在"可留（下一步）"里 ——
   本稿用**可见的「改重量」胶囊**替代了它；撤销仍是隐藏手势，这是已知缺口，
   后续在训练屏表头加一个不抢眼的「撤销」入口，而不是把说明写回正文。
3. **不做评价**：不写"还是 0 次""干得漂亮"（完成页那句已有，不扩散到统计页）。

### 4.6 动效 / 触觉（沿用，不在静帧里）

- 记录一组：新行 280ms 上移 6pt + 透明度；`light impact`。
- 休息结束：`heavyImpact`，不弹窗；剩 3 秒可加一次 `selectionClick`（待真机定）。
- 主按钮按下 0.975 / 100ms；弹层 260ms；破纪录 400ms 放大回落。
- 尊重 `prefers-reduced-motion`；不新增时长档（现有 `Motion` 五档够用）。
