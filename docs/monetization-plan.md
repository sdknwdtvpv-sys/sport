# 商业化方案（**没有账号登录体系**的前提下）

> 2026-10-01 出方案。产品文档里那句变现原则是准星：
> **「变现只押 AI 与云，不押记录本身」**（`PRODUCT.md` §10.3）。
> 这篇把"在没有账号体系的前提下怎么做"讲成可执行的三阶段，并列出**每一步要改什么、
> 要多久、有什么风险**。**本文只是方案，没有动代码。**

## 一、三条不能破的线（先立规矩，再谈钱）

1. **离线优先**：不付费也必须能完整记录训练 —— 付费墙挡在"记录"前面等于杀掉北极星
   （首次打开 → 完成第一次训练 ≥ 55%）。
2. **不强制注册**：现在没有账号，将来也不该"为了付费"逼人注册。商店账号（Apple ID /
   Google 账号）**天然就是身份**，够用了。
3. **默认不收集**：付费不能变成"多收一份数据"。新增的只有**购买凭据**，而且那是
   商店收的、我们只存校验结果。

> 还有一条商店硬规矩：**数字内容必须走应用内购买**（Apple 审核指南 3.1.1；
> Google Play 同样要求 Play Billing）。自己收钱（跳转支付宝/微信/网页）会被拒审或下架。

## 二、无账号怎么"认人"：商店收据 + 恢复码

| 手段 | 我们已有的 | 能解决什么 | 不能解决什么 |
|---|---|---|---|
| **商店账号（Apple ID / Google 账号）** | 不需要我们做任何事 | 同一平台内换手机、重装 → **恢复购买**按钮即可找回权益 | 跨平台（iOS 买过，安卓不认） |
| **恢复码**（已有，云备份在用） | `CloudBackup` 的匿名账号 + 恢复码 | 跨平台/跨商店找回权益；也解决"没有账号怎么同步" | 用户得自己抄下来（我们已经逼他勾"我抄在纸上了"） |
| **我们自己的账号体系** | 没有，也**不建议现在做** | —— | 一旦做，就要处理手机号/邮箱、注销、数据出境…… 与"默认不收集"直接冲突 |

**结论**：权益的"真相"放两处 —— **商店收据（本地 + 可选服务端校验）** 是主，
**恢复码绑定**是跨平台兜底。这两样都不需要用户注册。

> **想做「微信登录」这种账号体系？** 先读 `docs/wechat-login-feasibility.md`：
> Apple 审核指南 4.8 把 WeChat Login 写进了触发条件，用微信登录**必须配 Sign in with Apple**，
> 而且移动应用**拿不到微信手机号** —— 那不是「加一个登录按钮」，是 13–17 人日的账号体系改造。

## 三、四种变现模式，以及我的推荐组合

| 模式 | 卖什么 | 需要服务端吗 | 与"离线优先"冲突吗 | 我的判断 |
|---|---|---|---|---|
| **A. 一次性买断「Pro」** | 本地增强：更细的进步分析、计划模板全部解锁、导出格式（Excel/PDF）、批量编辑历史 | ❌ 不需要 | ❌ 不冲突（纯本地能力） | ✅ **第一阶段就做这个** |
| **B. 云备份订阅** | 加密备份到我们的服务器（有真实成本：存储+流量） | ✅ 需要（已有极薄后端） | ❌ 不冲突（核心是本地，云是加成） | ✅ **第二阶段**，与 A 并存 |
| **C. AI 建议订阅** | 规则引擎之上的个性化建议（产品文档押的那一半） | ✅ 需要算力（**超出"极薄后端"**） | ❌ 不冲突 | 🟡 **第三阶段**，要先算成本 |
| **D. 打赏/赞助** | 无 | ❌ | ❌ | ⬜ 不推荐做主线（金额小、审核也麻烦） |

**推荐组合**：**卖断本地增强（A）→ 卖云（B）→ 卖 AI（C）**，三层互不依赖，
也可以只做前两层就把商业模式跑通。

### 为什么是"买断 + 订阅"而不是纯订阅

* 本地能力（A）**没有持续成本**，做成订阅会显得贪；买断一次、终身可用，符合工具类心智。
* 云备份（B）**有持续成本**（每份备份占存储、每次恢复走流量），订阅才公平。
* 两档并存还有一个好处：**用户可以不订阅而只买断**，我们不会因为"订阅疲劳"丢掉那部分收入。

## 四、三个阶段的具体动作

### 阶段 P0：买断制 Pro（**不需要服务端**）

| 项 | 内容 |
|---|---|
| 依赖 | `in_app_purchase`（Flutter 官方插件，两端都支持） |
| 状态存哪 | 本地库新增一张 `entitlement` 表（**不联网也能用**）+ 启动时静默 `restorePurchases` |
| 卖点（第一版） | ① 进步页的"分动作趋势/周期对比"；② 计划模板全部解锁；③ 导出 Excel/PDF；④ 批量改历史（原来只有逐条） |
| 界面 | 「我 → 偏好设置」下面新增一行「练了么 Pro」；**不做全屏付费墙**，只在被锁功能处给一行说明 + 一个按钮 |
| 政策/合规 | 隐私政策新增一小节「购买与支付」：**支付由 Apple/Google 处理，我们只保存"是否已购买"这个布尔值**；商店表单"收集什么"保持不变（支付信息不是我们收集的） |
| 工时 | **5–8 人日**（含两端沙盒测试、恢复购买、退款路径、测试） |
| 风险 | 本地校验可被越狱设备绕过 —— 离线优先的必然代价，接受；真要防，P1 的服务端校验顺带解决 |

### 阶段 P1：云备份订阅（复用现有恢复码）

| 项 | 内容 |
|---|---|
| 现状 | 云备份已经能用（匿名账号 + 恢复码 + 端到端加密），只是**没收费**、也**没配额** |
| 要做的 | ① 订阅商品（月/年）；② 服务端做**收据校验**（Apple `verifyReceipt` / Google Play Developer API）并把"这个恢复码有权益"记下来；③ 免费额度（例如 1 份备份 + 最近 30 天）与 Pro 配额（多版本 / 不限量） |
| 服务端改动 | **仍然不做任何计算**：加一张 `entitlement(recovery_code, platform, expires_at)` 表 + 一个校验接口。这与"极薄后端"的边界一致 |
| 跨平台找回 | 用恢复码绑定；用户在 iOS 买、在安卓登录同一个恢复码 → 权益跟着走（这时才需要那点服务端逻辑） |
| 政策/合规 | 「购买与支付」那节补一句跨平台绑定；云备份那节写明配额与到期后**数据不会删**（降级为只读/停止新备份，保留 30 天） |
| 工时 | **8–12 人日**（含服务端校验、沙盒订阅测试、到期/退款/恢复全路径） |
| 风险 | 订阅的审核与退款流程比买断复杂；**到期后必须让用户仍然能导出自己的数据**（否则就是"用数据绑架"） |

### 阶段 P2：AI 建议订阅（要单独算账）

* 产品文档押的就是这一半（「建议采纳率 ≥ 60%」是它的指标）。
* **但它需要服务端算力**（至少要把历史脱敏后送出去算）—— 这与"数据不出设备"的
  现有姿态**正面冲突**，必须做成**显式同意 + 可撤回 + 只送必要字段**，并更新政策、
  事实表、隐私标签、软著说明书。
* 我建议：**先不做**。等 P0/P1 跑起来、有真实付费意愿的数据，再决定要不要为它
  破坏"数据不出设备"这条卖点。

## 五、每一阶段都要同步的东西（这个仓库的规矩）

| 类别 | 具体 |
|---|---|
| 代码 | 权益服务（`lib/billing/`）+ 被锁功能的判断（**只藏不删**）+ 恢复购买入口 |
| 测试 | 沙盒购买 / 恢复 / 退款 / 到期降级 / 离线时仍能用已购功能（**每条都要有测试**，否则会像"默认开"那次一样漂） |
| 政策 | `docs/privacy-policy.md` + `.en.md` 新增「购买与支付」；事实表与商店表单重新对账（`privacy-audit` / `check-store-forms` 会逼着改） |
| 商店 | Apple：App 内购买项目（App Store Connect 里建商品）；Play：订阅/一次性商品；国内商店：各自支付 SDK（**这一摊最脏，建议国内版先不做内购**） |
| 软著 | 说明书要写"付费功能怎么用"（有内购就要写清楚哪些收费） |
| 版本 | 只要动 `app/` 就切版（本仓库的规矩），并且**真机重装** |

## 六、定价建议（先验证，不拍死）

| 档 | 国内 | 海外 | 理由 |
|---|---|---|---|
| Pro 买断 | ¥25 | $3.99 | 工具类买断的常见价位；低到"少喝一杯奶茶" |
| 云备份订阅 | ¥6/月 或 ¥48/年 | $1.99/月 或 $14.99/年 | 只覆盖真实成本 + 少量毛利 |
| AI（若做） | ¥15/月 | $4.99/月 | 需要真实算力成本支撑 |

## 七、我建议的下一步（等你点头）

1. **先做 P0**（买断 Pro，5–8 人日）：它不需要服务端、不破坏任何现有承诺，
   而且能在**两周内**让"有没有人愿意付钱"这个问题有答案。
2. P0 上线后看两个数：**付费转化率**与**首练完成率有没有被付费入口拖低**
   （第二个是北极星，掉一点我就不做 P1）。
3. P1 等你拿到 Apple 开发者账号 + 服务器（`docs/backend-design.md` 阶段 4）之后再做。

## 八、需要你定的三件事

1. **卖点选哪几个**：我上面挑的四个（周期对比 / 计划模板 / Excel 导出 / 批量改历史）
   是不是你想要的？可以换 —— 但**不能**把"记录训练"本身锁起来。
2. **国内版要不要内购**：国内商店的支付各搞一套，脏且慢。我建议**国内先免费**、
   海外走 App Store / Play 内购。
3. **云备份的免费额度**：我建议「1 份备份 + 最近 30 天」，你觉得够不够。
