# 练了么 · 「不够大气」方向重定（2026-11-12）

> **触发**：用户看过 v2.3.0 真机后说「不够大气」，并点名用 `oil-ui-pro` 做。
> 按该 Skill 的「回改」判断，这是**方向级信号**，不是细节问题：不再修字号/间距/边距，
> 重新定义「大气」的可观察决定，并用**两个首屏小样**让用户选。
>
> **范围**：首页 + 进步页的首屏；训练/总结/选择器只做"已确认清单"核对，不重画。
> **边界**：只写 `prototype/grand/` 与本文档；不改 `app/`、不动 `dist/`、不 push。
>
> **一句话原则**：**大气 = 一屏里更大的尺度、更少的容器、更长的呼吸；不是更大的卡、更亮的光。**

---

## 0. 先判断：为什么这次不能继续修细节

v2.3.0 已经把结构减负做完了：首页 3 行 + 汇总副标题 + 事实行、训练目标进表头、
进步只留 hero/趋势/入口、总结小结收起、3 Tab。用户在**结构没错**的前提下说「不够大气」，
说明问题在**视觉尺度与分量**，继续加/减 1px、换 1 个字号不会改变感受。

因此这一轮只做两件事：

1. 把「大气」翻译成**可观察、可验收的决定**（§1）；
2. 做两个**方向性**的首屏小样：A「编辑大字」/ B「整块剧场」，让用户选方向（§2–§4）。

**不做什么**：不修 v2.3 已确认的结构；不加玻璃、大阴影、彩色氛围光；不把字号缩小来"腾空间"。

## 1. 「大气」翻译表

> 用户的原话是感受，不是改法。每一行都必须落到"截图上能量出来的值"。

| **不够大气 → 尺度** | 页标题、关键数字、动作名、行高、CTA 高度 | 页 28 / 数字 34 / 动作 17 / 行约 46 / CTA 64 | **页 40 / 数字 56 / 动作 22 / 行 56 / CTA 72** | **页 40 / 数字 56 / 动作 22 / 行 56 / CTA 72** |

**不把「大气」翻译成这些**（这是本轮明确排除的）：

- 更大的卡 / 更多的卡片 / 每个区块都套一层容器；
- 更大的阴影、发光、玻璃、彩色氛围光；
- 更亮的橙、把橙色铺满整屏；
- 更小的字 / 更紧的行高 / 把元素缩到边角。

> **判定口径**：两个方向都必须比现状**更大**（字/数字/行/CTA），
> 同时**更少**（更少的容器、更少的线、更少的并列块）。
> 如果一个大样只是把现状的卡片放大，它不叫方向，叫换尺寸。

## 2. 调性：安静，但有重量

在「先定调性」这一层，两个方向都不离开 v2.3 的安静底色：

| 刻度 | 取值（1–10） | 依据 |
| --- | --- | --- |
| 能量（安静 ↔ 喧闹） | **3**（偏安静） | 健身房暗光、单手、组间 60 秒；不喧闹 |
| 分量（轻 ↔ 重） | **8**（偏重） | 力量训练；用户要"大气"而不是"轻巧" |
| 密度（疏 ↔ 密） | **2**（疏） | 每屏只有一个主任务；空白是节奏 |
| 完成度（粗粝 ↔ 精致） | **8**（精致） | 4pt 对齐、tabular、少线 |
| 严肃度（活泼 ↔ 庄重） | **7**（偏庄重） | 不是娱乐 App，但也不是工业仪表 |

**差异只在"怎样获得重量"**：

- A 用**尺度与留白**获得重量（大字、无卡片、full-bleed 图）；
- B 用**色块面积**获得重量（一整块 surfaceHi 舞台）。

两方向都保留暖黑 `#090706` 与橙 `#E2663A`；不新增色相，不做彩色氛围光。

## 5. 两方向差异（一屏看差在哪）

| 维度 | A · 编辑大字 | B · 整块剧场 |
| --- | --- | --- |
| 大气的来源 | 尺度断层 + 留白 + full-bleed | 一个色块的质量 + 块内唯一橙点 |
| 首屏容器 | **没有卡片**，一条裸列表 | **一个大块**，块内承载行与 CTA |
| 页标题 | 40（H1 即版面） | 40（标题在块外） |
| 数字 | 56，独立大字 | 56，嵌在块里 |
| 橙色 | CTA + 图表/链接，≤10% | 块内一个点（首页 CTA / 进步曲线） |
| 留白 | 32 页边 / 40 区块 / 大段空 | 28 页边 / 40 区块 / 块内更紧 |
| 记忆点 | "一张训练杂志跨页" | "黑底上一块训练台" |
| 气质 | 编辑、冷静、有版面感 | 温暖、重、仪式感 |
| 最大风险 | 大字号 2.0× 与外壳标题重排 | 大块高度/对比度/2.0× 拥挤 |
| 迁移到训练/总结 | 更自然：同一套 H1/行/CTA 语法 | 要决定"哪些内容配一块"；更依赖容器 |

## 6. 推荐：A（B 作为更重的备选）

**推荐 A「编辑大字」**，理由：

1. **它直接回答了"不够大气"的主因**：v2.3 是结构对、尺度小；A 用 40/56/22/56/72 的字阶断层与 32/40 留白把版面"立起来"，不是再加一层容器。
2. **它不把 v2.3 刚减掉的"块"重新长回来**：首页无卡片，列表就是版面；B 虽然只有一块，但那一块在视觉上仍是一个大容器。
3. **它更容易迁移**：训练屏、总结页都可以沿用"H1/行/CTA"的语法；B 的色块语法要先决定哪些屏配块，容易变成"每屏一张大卡"。
4. **风险更可测**：A 的风险集中在 40/56 两档字号与外壳标题，能在 1.5×/2.0× 上单独验证；B 的风险是块高 + 对比度 + 2.0× 拥挤，组合更多。

**B 不是陪跑**：如果用户想要"更重、更有仪式感"，B 的色块质量更直接；但推荐先看 A。

**不推荐现在拼接 A+B**：会把"无卡片"和"大块"两种语法混在一屏，记忆点会消失。

### 8.3 顶栏是最大实现风险（两方向都有）

现状 v2.3.0 的「今天 / 进步」标题来自**外壳 `AppTopBar` 的 28pt**。两个样本都把 40/34 的大标题画在**内容层**：

- 方案 1（推荐）：外壳顶栏在首页/进步改成**只留右侧动作区**，标题交给内容层；这样不双写标题，但 `AppTopBar` 的跨屏结构要改。
- 方案 2：直接把 `AppTopBar.title` 的 28 改成 34/40；这会影响所有 Tab 的顶栏，训练/我的等页也要重新看比例。
- 方案 3：只在首页/进步用较大的内容标题，外壳仍 28 —— 会出现**两套标题**，不可取。

**这一条必须在方向拍板后单独确认**，否则实现会做成"两遍标题"。

### 8.4 信息可达性

- 两个方向都**不删信息、不新增入口**：首页仍是 3 行动作 + 汇总副标题 + 最近/本周事实行；
  进步仍是 hero + 趋势 +「全部数据 · 部位 / PR」入口；训练/总结/选择器的结构不动。
- A 的「全部数据」在首屏底部一行；B 的入口在大块下方一行 —— 都在首屏可见，点击次数不变。
- 唯一变化的可达性是**页面标题进入内容层**（见 §8.3）：若选方案 1，外壳顶栏不再重复标题；
  若选方案 2，所有 Tab 顶栏要复核；不要出现"两遍今天"。
- 本页小样没有出现"为了大气隐藏功能"的情况；这是选方向，不是减功能。

## 9. 2.0× 风险（必须验）

| 位置 | 1.0× | 2.0× 风险 | 处理 |
| --- | --- | --- | --- |
| A H1 | 40 | 80；与日期/铃铛挤，可能两行 | 允许两行，头部用 `Wrap`/可增长，不固定高度；内容可滚动 |
| A/B 数字 | 56 | 112；`3 位数字 + kg` 可能超宽 | `FittedBox(scaleDown)` 只用于数字；保留 56 的语义；不要压正文 |
| B 块 | min-height 520 | 块内文字变大，块更高/更挤 | 用 `min-height` 不写死高度；块内可滚动或页面滚动；不要裁切 |
| 行 | 56 | 44 的动作名可能溢出 | `min-height:56` + 动作名 `maxLines:2`/ellipsis；不能固定裁掉 |
| CTA | 72 | 按钮字 40，内边距挤 | 高度用 `min-height:72`，随字号增长；触控区不变 |
| B 标签 | 12 text2 | 块内对比度 | 块内不用 text3；保持 text2 |
| 顶栏 | 28→34/40 | 与状态栏/铃铛 | 见 §8.3；不要让标题进入状态栏 |

**判定**：1.5×/2.0× 下不出现裁切/重叠/关键动名词被截断；若 A 的 H1 在 2.0× 下必须缩到 28 才不破，说明方向实现方式要换（内容层滚动，不要压外壳）。
