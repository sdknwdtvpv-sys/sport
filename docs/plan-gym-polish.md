# 健身房现场细节：v1.53 这一批（2026-10-05 定）

> 起因：用户 2026-10-05 带着 v1.52.0 去健身房实际练了一次，反馈「整体没大问题，
> 但很多细节可以做得更好」，随后让我把下面 1–8 逐条修掉。

这份文档是**这一批的排期与判据**。每一行的状态做完就改，**不留在脑子里**。
与别的批次一样，四条规矩一条不少：**有测试**（新行为要有自测，能防退化的要有负向用例）·
**同步文档**（`screens.md` / `interaction-spec.md` / `feature-backlog.md` / `CHANGELOG.md`，
以及政策里会因此变成假话的说法）· **`./verify.sh` 六层 + 干净克隆里也绿** ·
**模拟器/真机截图当证据**，没做完的**如实写出来**。

## 这一批的红线（做之前先钉死，免得改着改着越界）

1. **`1 次点击 = 1 组` 不动摇**（北极星的那条硬指标）。新增的任何控件都不许让"记一组"多一次点击。
2. **不新增系统权限**。休息结束的提示复用已有的 `POST_NOTIFICATIONS` 与
   `lianleme_training_reminder` 那条渠道 —— 加权限就要同时改中英政策、隐私事实表、两张商店表单。
3. **不新增埋点字段 / 事件**。这一批只改交互；换动作用已有的 `exercise_switch` 计一次点击
   （意图与代价相同），所以政策与商店表单一个字都不用动。
4. **身体数据与训练数据仍然不出设备**：新功能一律本地。
5. **动原生（常亮 / 通知）的部分必须真机验**，验不了的（比如 Doze 下的延迟）如实写在文档里。

## 明确不在这一批里做的（免得被当成漏了）

* **休息结束的通知**在 iOS 上不加：iOS 那边已经有 Live Activity（锁屏/灵动岛倒计时），
  再来一条通知是重复打扰。**Android 上没有等价物，所以只做 Android**。
* **换动作不写"为什么换"的埋点理由**（要新增字段 → 碰政策与商店表单，违反上面第 3 条）。
* 大字号只保证**不溢出、可读**，不承诺"重新排版出一套大字版式"。

## 顺手修掉的一处守卫脆弱性（不是这一批的功能，但它是这一批暴露的）

`tool/lib/collect-repo.mjs` 的自检里有一条"★ 真仓库：dist 读得出来"。它在干净克隆里
第一遍能过（没有 `dist/` → 如实说没有）、**第二遍必红**：`verify.sh` 自己会往
`dist/copyright/` 写软著材料，于是目录在、产物不在，旧判据要求 `files.length > 0`。
后果是"在同一个克隆里跑两遍门禁会红"—— 而 CI 每次都是新克隆，所以只有本地会碰到。
判据已补上这种形态（目录在、产物与软著都空 → 允许），**开发机上 dist 里一直有 APK，
所以 `readDist` 真坏掉时这条照样会红**。
