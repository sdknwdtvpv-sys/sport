## 逐条

### 第 1 条 · 「指标填了数之后，就不显示名称了」

**现状**（截图 1：身体数据页，「更多指标」卡里腰围/肌肉量两格，其中一格已经填了 `183`）：
`_smallField()` 把名字写在 **`hintText`** 里（`'腰围 cm'` / `'肌肉量 kg'`）——
**一输入就消失**，于是用户看着两个数字不知道哪个是腰围、哪个是肌肉量。身高那格同理。

**做法**：名字改成**常驻标签**（字段上方一行小字），`hintText` 只在真的需要举例时留
（如「例如 82」）。备注那一格同样处理（它的名字也在 hint 里）。

### 第 2 条 · 「撤回同意这种设置类的入口全部收纳到设置里，这里不展示」

**现状**（截图 2：身体数据页下半屏）：两条撤回入口直接铺在身体数据页上 ——
「撤回我的同意」（`body-revoke`）与「撤回「读系统健康」的同意」（`health-revoke`），各带一段说明。

**做法**：两条**搬到「设置 → 隐私与关于」**（那一屏已经有「隐私开关 / 对外文本」两组，
再加一组「撤回同意」），确认弹层、说明文案、key 全部原样带过去（**文案一个字不改**：
"撤回的是同意、不是数据"这句是 PIPL 口径，不能在路上被简化）。
身体数据页上**一个都不留**。

⚠️ 连带的三件事：
* 「隐私与关于」要多认识 `ProfileRepository`（它已经有了）与**健康库那道同意**的状态；
* `test/` 里按 `body-revoke` / `health-revoke` 定位的用例要跟着改成从设置页进
  （那些 key 不改名，只是换了住户）；
* 「身体数据」页顶部那句「单独同意」的门**一个字不动** —— 搬走的是"撤回"，不是"征得同意"。

### 第 3 条 · 「这个页面的输入按键，没办法退出」

**现状**（截图 1/2 都能看到）：身体数据页点开数字键盘之后**没法收起来** ——
点空白处不收起（Flutter 默认行为就是不收），而 iOS 的数字键盘**没有回车/完成键**。

**做法**（两条一起给，缺一条都还是"退不出去"）：
1. **点空白处收起键盘**：给这一页的字段加 `onTapOutside`（也可以整页兜一层
   `GestureDetector`），点任何非输入区都 `unfocus()`；
2. **一个看得见的「完成」**：键盘弹出时在页面顶部那条（返回箭头的右侧）出现一个
   「完成」文字按钮，点它收起键盘并失焦 —— 用户不必知道"点空白"这件事。

### 第 4 条 · 「计划里面，有些不在健身房练的。能否前置选择下在什么场景练，然后匹配对应的动作和计划」

**现状**：「今天练什么」只按**部位**挑动作（胸 3 个 / 背 2 个…），完全不看器械 ——
于是常年在家练的人被排到「器械推胸」「绳索夹胸」。

**做法**：加一个**训练场景**，前置选、并且**真的进筛选**。

| 场景 | 允许的器械 |
|---|---|
| **健身房**（默认，与现在完全一样） | 全部（barbell / dumbbell / machine / cable / kettlebell / band / bodyweight） |
| **家里** | dumbbell / band / kettlebell / bodyweight |
| **徒手**（出差、户外） | bodyweight |

* **存在哪**：`user_profile.training_scenario`（**库版本 29**，null = 健身房 —— 老库升上来
  就是"没选过"，而"没选过"的现状就是按全器械推荐，所以默认值就是健身房）；
* **在哪儿选**：「计划」页顶部一行 chips（「在哪练 · 健身房 / 家里 / 徒手」）——
  这一屏本来就是"我的计划长什么样"的地方；选完**立刻**按新场景重排今天的安排并落库
  （第 6 条那次落库的 `day_plan` 表）；
* **怎么生效**：`ExerciseRepository.search` 加一个 `equipmentIn`（集合），
  `TodayPlanner.planToday / planForGroup / reroll` 都带上它 —— 与现有的
  「器械筛选」是同一条路（选择器里那一行 chip 早就在用），不新写一套挑选逻辑；
* **首页那张卡的副标题**跟着显示当前场景（如「今天练 上肢 · 家里」）——
  不然用户会奇怪"我明明选了家里，怎么还给我推这个"。

⚠️ **不在这一条里做的**（写清楚，免得以后有人以为漏了）：
* 计划**模板**（`routine` 里那几条内置模板）**不按场景重写** —— 它们是内容，
  重写要一套新数据；这一条先让"今天练什么"这件事对上场景；
* 不加更多场景（"酒店健身房""户外"）—— 三个够用，多一个就多一份要维护的映射。

### 第 5 条 · 「看最上面 玻璃质感完全 bug了 回退吧」

**现状**（截图 3：数据页，iOS）：**顶栏那块玻璃是坏的** —— 标题「数据」与页面内容
（「按时间看」「导出 CSV」）互相叠影、出现重影文字。

**做法**：**把顶栏那块玻璃整个回退**（用户原话"回退吧"），也就是 v1.66.0 第 2a 条里
"顶栏 + 浮层"里的**顶栏那一半**撤掉：

* `AppTopBar` 不再包 `GlassSurface`（`glass-top-bar` 这个 key 一起消失）；
* 外壳的 iOS 布局回到"顶栏在 `Column` 里占位"（不再浮在内容之上）；
* 各屏滚动内容的顶部留白 `AppTopBar.reservedSpaceFor` 一并撤掉（6 处）；
* **底栏的玻璃不动**（用户没提它，而且它一直是好的）；
* **浮层的玻璃不动**（`showAppDialog` / `showAppSheet` 是这一版新加的，用户没提；
  它们背后是被压暗的页面、有东西可折射，与顶栏那种"背后就是页面内容"是两回事）。

⚠️ 顺手记一条**教训**（写进 CHANGELOG）：顶栏这一块的失败方式和我在
`glass_surface.dart` 文件头写下的那条前提是同一个 —— **玻璃必须背后有东西可折射**；
底栏之所以一直好，是因为它下面真的在滚内容，而顶栏把页面内容盖住之后，
平台视图与 Flutter 内容的层叠关系在真机上出了重影。**真机才看得见，模拟器看不出来。**

## 追加（2026-10-09 深夜）：底栏换成**苹果原生的 `UITabBar`**

他随后发来一份 `StellarTabBar.swift`（另一个 SwiftUI 项目的底栏外观文件）说「直接复用」，
被追问之后明确了意图：**「我想要苹果原生的 uitabbar」**。

⚠️ **那份文件不能直接用**：它靠 `UITabBar.appearance()` + `.toolbarBackground(for: .tabBar)`
生效，而我们的 App 是 **Flutter** —— iOS 侧一个 `UITabBar`、一个 SwiftUI 视图都没有
（`ios/Runner/` 里只有 AppDelegate/SceneDelegate + 6 个桥文件）。拖进工程**编译得过、
屏幕上一个像素都不会变**。能复用、也真的复用了的是**它那套 `UITabBarAppearance` 的写法**。

**做法**：iOS 的底栏换成一个**真的 `UITabBar`**（新建 `ios/Runner/NativeTabBarBridge.swift`
+ `lib/core/native_tab_bar.dart`），不再自己画 `UIGlassEffect`：

* 外观：`UITabBarAppearance`（选中/未选中的图标与文字色、顶部分割线）—— 与 Stellar 同一套 API；
* 五项：SF Symbol + 中文标签（与 `AppTabBar.tabs` 同序），选中项由 Dart 喂 `setSelected`；
* 点击：原生 `didSelect` → 通道 `onTabSelected` → 外壳 `_selectTab` ——
  ⚠️ `UiKitView` 必须给 **`EagerGestureRecognizer`**（真控件自己接触摸）。
  v1.66.0 那块玻璃**正好相反**（空集合，让触摸穿透到 Flutter 侧我们盖的透明热区）；
* 连带删掉的死代码：`AppTabBar` 里所有 iOS 分支（浮动/玻璃/跟手胶囊/正中强调圆）、
  `dragIndex` 参数、外壳的 `_glassDrag` 与 `_tapPaging`；
* Android 那一支**一个像素都没动**（仍是 Flutter 画）。

**验到什么程度**（模拟器 iPhone 18 Pro Max / iOS 27）：
`flutter build ios --simulator` → 装上 → 截图，**苹果那个浮动液态玻璃胶囊真的出来了**
（五格、选中「训练」= 我们的橙、未选中 = 我们的灰）。
**真机验过**（2026-10-09 深夜，iPhone 17 Pro，`tool/ios-device-run.sh`：`BUILD SUCCEEDED` →
`App installed` → 拉起成功，`devicectl` 读到 `1.66.0 / 81`）：
* `xcrun devicectl device capture screenshot` 两张连拍 —— 第一张停在「我的」、底栏选中「我的」；
  第二张停在「进步」、选中跟着到「进步」。**页面与选中一起换 = 点击这条路是通的**
  （正是模拟器上验不了的那一条：`simctl` 不能注入点击、本机也没有 `idb`/`cliclick`，
  而 Flutter 集成测试注入的事件进不了平台视图）；
* 真机图存 `docs/images/v166-native-tabbar-iphone-1.png` / `-2.png`。
⚠️ 那一版**版本号仍然是 1.66.0**（本地改动还没切版）—— 同一个版本号下改过 `app/` 就必须
重出包/切版，这条纪律见 `docs/release-checklist.md`「构建链」那一行。
