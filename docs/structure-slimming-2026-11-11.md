# 练了么 · 结构减负（IA 精简 + 留白节奏）· 2026-11-11

> **用户反馈**：v2.2.0 真机「整体排布太局促了，每一屏塞的东西都太多，能不能再优化下结构」。
>
> **这一轮不是换皮**：不改颜色、不改圆角、不加重阴影。只做三件事：
> **每屏只留一个主任务 · 把低频内容下沉 · 用留白和分组把剩下的东西排开**。
>
> **边界**：只写 `docs/structure-slimming-2026-11-11.md` 与 `prototype/slim/`；
> 不改 `app/`、不动 `dist/`、不 push、不重出商店截图。

> **一句话原则（可写进代码注释）**
> **一屏一个主任务；其余靠下沉和渐进披露，不靠缩小字号。**

---

## 0. 一页结论

| 屏 | 主任务 | 现状首屏 | 减负后首屏 | 砍掉 / 搬走 |
| --- | --- | --- | --- | --- |
| 首页 | 开始今天的训练 | 3 块 / 1 卡 / 6 个字号 | **2 块 / 1 卡** | 4 行→3 行、「…还有 2 个动作」、独立「最近一次」、7 点周节奏 |
| 训练 | 记下当前这一组 | 4 块 / 1 卡 / 7 个字号 | **3 块 / 1 卡** | 4 段进度、「本场」摘要、独立目标带、第 N 组行、右 2 icon |
| 进步 | 一眼看到本周容量与趋势 | 5 块 / 1 卡 / 6 个字号 | **3 块 / 1 卡** | 部位分布 / 个人纪录 / 最近训练 → 全部数据 |
| 我 | 我是谁 + 我的进度 | 4 块 / 3 卡 / 5 个字号 | **2 块 / 1 卡** | 身份卡+进度卡合并；版本 → 设置；重复标题 |
| 选择器 | 找到并选一个动作 | 5 块（搜索 + 3 行筛选 + 列表）/ 0 卡 | **3 块 / 0 卡** | 3 行筛选 → 一个筛选入口；每行默认重量口径删除 |
| 总结 | 确认这次训练 | 6 块 / 5 卡 / 6 个字号 | **3 块 / 2 卡** | 三统计合并一行；笔记/下一次/拉伸默认收起 |

**结论**：问题不是"字号太大/太小"，而是**每个屏幕同时有 3–5 个并列任务**。

补一个量感：v2.2.0 首页那张今日训练卡本身就有 **402pt 高、卡内 9 行**（4 行动作 + 标题/表头/按钮/「还有」/最近/周），
而页面底栏前还空 221pt —— **内容全挤在上半张卡里，下面却空着**。这就是用户说的"局促"：不是屏幕小，是元素没有分层。
所有减负都靠"合并同类 + 低频下沉 + 渐进披露"，不靠把字缩小或把卡变紧。

## 1. 先测量（v2.2.0，iOS 440×956）

### 1.1 方法

- 以 `store-assets/screenshots-ios/*.png`（1320×2868，440×956）为准；
  **首屏 844pt = raw 0–2532px**。真机 `402×874` 的 `v220-device-home` 用于核对首页。
- 逐屏数：**信息块**（视觉上独立的一段/一张卡）、**卡片**（有 surface 底的容器）、
  **首屏字号种数**（从源码 + 截图的 `fontSize` 实际使用去重）、
  **区块间距**（源码中的 `SizedBox` / padding）、**左右边距**（ListView 的 `s5=20`）。
- 内容高度用"逐行亮度 + 卡片 surface 扫描"估：首页内容结束约 raw 1877（**625pt**），
  底栏顶约 846pt，空尾 **221pt**；"我"内容结束约 645pt，空尾 **201pt**。
- 所有屏幕的现状都来自 v2.2.0 截图，**不是 v2.1 旧图**。

### 1.2 测量表

> "内容行"= 首屏能数出来的独立信息行（含卡内主行，不含图标与纯装饰）；
> 它比"信息块"更能说明"塞了多少东西"。

| 屏 | 首屏 844 内信息块 | 卡片 | 首屏字号种数 | 内容行 | 区块间距 | 左右边距 | 页面总内容高 |
| --- | --- | --- | --- | --- | --- | --- | --- |

### 1.3 现状的 5 个结构问题（不是审美问题）

1. **主任务不唯一**：首页同时"告诉今天练什么"和"让你看坚持"；进步同时"看总量/看趋势/看部位/看 PR/看最近"；总结同时"庆祝/写笔记/看下次/看拉伸"。
2. **同类信息不合并**：连续 / 本周 / 时长三格并列；身份 / 等级 / 成就三张卡；最近一次与周节奏两行。
3. **低频内容占首屏**：部位分布、个人纪录、最近训练、版本号、拉伸建议。
4. **一屏卡太多**：我 3 张、总结 5 张；卡与卡之间靠 20pt 缝，视觉上"全是块"。
5. **间距没有节奏**：同一屏 8/12/16/20 混用；页面边距 20，卡内边距有 16 和 20 两种；结果是"内容挤在一起，但页面底部又空"。

## 2. 判定标准（本轮执行）

| 项 | 建议值 | 怎么执行 |
| --- | --- | --- |
| 每屏主任务 | **1 个** | 首页=开始；训练=记录当前组；进步=看本周；我=身份+等级；选择器=选动作；总结=确认完成 |
| 首屏信息块 | **≤3 块** | 主卡 + 至多 2 个辅助块；超过就合并/下沉 |
| 一屏卡片 | **≤2 张** | 纯数字/纯文字用细线分节，不包卡 |
| 页边距 | **20 → 24**（`s6`） | 所有一级/二级页统一 24；不按屏微调 |
| 区块间距 | **28 / 32 两档** | 组内 `s5=20`、区块 `s7=28`、大段 `s8=32`；不再用 8/12/16 做区块间距 |
| 卡片内边距 | **16 → 20** | 统一 `s5`；只有嵌套小行允许 16 |
| 同类合并 | 事实行、统计行、角标 | 连续/本周/时长 → 一行；三统计 → 一行；身份+等级 → 一张卡 |
| 低频下沉 | 全部数据 / 设置 / 编辑 / 展开区 | 有现有入口优先，不新开页面 |
| 文案 | **砍约 30%** | 删解释、删重复标题、删"还有 N 个"这类可推断信息 |

> **为什么不继续缩字号**：v2.2.0 已把字号抬到 17–22，再缩会把"健身房暗光可读"打回去；
> 这一轮减的是**元素数量与层级**，不是字号。

## 3. 六屏「保留 / 合并 / 下沉 / 删除」四列表

### 3.1 首页「开练」

| 保留 | 合并 | 下沉 | 删除 |
| --- | --- | --- | --- |
| 顶栏（今天 / 日期 / 铃铛）<br>今日训练卡（1 张）<br>「开始训练」<br>「编辑」 | **最近一次 + 本周节奏 → 一行**：`最近 11/7 · 本周 0 天`（底栏上方，细线分隔）<br>卡内动作 4 行 → **3 行 + 卡头「6 个动作 · 18 组」** | 完整 6 个动作的排序 / 换动作 / 从模板载入 → **现有「编辑」**<br>容量/上次明细 → **进步 → 全部数据**（现有）<br>周节奏的 7 个点 → 不单独占行（合并成天数） | `…还有 2 个动作`（编辑里可推断）<br>独立「最近一次」行<br>7 点周节奏条<br>首页上的 `1,280 kg` 容量（进进步） |

- **移到哪 / 丢不丢信息 / 新入口**：第 4+ 个动作进现有编辑，**不丢**；容量进进步，**不丢**；无新入口。
- **代价**：首页看不到第 4 个动作名，需要一次「编辑」；卡头写「6 个动作」交代清楚。
- **首屏结果**：2 块（卡 + 一行事实）/ 1 卡。

### 3.2 训练「记录当前组」

| 保留 | 合并 | 下沉 | 删除 |
| --- | --- | --- | --- |
| 顶栏：动作名 / `动作 1 / 4` / 一个 `⋯`<br>组表（当前行高亮）<br>记录键（88pt）<br>上一个 / 下一个 | **目标进表头**：`本次 0 / 4 组 · 目标 4 × 8–10`<br>「第 N 组」→ 组表当前行 + 按钮本身就是当前组 | 换动作 / 动作说明 / 改重量 → **`⋯` 菜单**<br>完整动作要领 → **现有动作详情页** | 4 段动作进度条（与 `1 / 4` 重复）<br>独立「今天的目标」带<br>`本场 0 / 16 组 · 已练 00:00`<br>顶栏右两个 icon（↔ 与 ⓘ）<br>独立的「第 N 组」行 |

- **丢不丢**：目标仍在表头；换动作/说明/改重量在 `⋯`；1 次点击 = 1 组不变。
- **新入口**：`⋯` 菜单（同屏，不跳页）；动作说明仍可进详情页。
- **首屏结果**：3 块（顶栏 / 组表 / 记录区）/ 1 卡。

## 4. 全局留白 / 边距 / 间距 / 字阶

## 7. 风险与「不要做」

### 7.1 风险

1. **可达性**：部位/PR/最近下沉到全部数据；如果首屏没有任何提示，用户会以为功能消失。
   缓解：保留一条 `全部数据 · 部位 / PR` 入口（本静帧已画），并在发布说明里提一次。
2. **首页只显示 3 行**：第 4+ 个动作不可见；如果用户直接开始，可能练的不是完整计划。
   缓解：卡头写「6 个动作 · 18 组」；编辑仍可看全部；真机观察一周再决定是否回 4 行。
3. **训练目标收进表头**：首练用户可能找不到"今天做几组"。
   缓解：表头第一行就是 `本次 0/4 组 · 目标 4×8–10`；大按钮上仍有值。
4. **总结渐进披露**：笔记默认收起，用户可能不写。
   缓解：笔记仍自动保存；展开区标题写「写一句 / 下次 / 拉伸」；不要把它做成新页面。
5. **我页空**：合并后只剩 1 卡 + 成就行，高屏会空。
   缓解：成就行钉在底栏上方做"页脚"，不要把版本号/设置铺回来。
6. **新增 s7=28**：如果不加令牌、直接写 28，会破坏间距真源。
   缓解：`s7` 进 `theme.dart`，或统一用 24/32 两档，并在 `spacing_grid_test` 里写清。
7. **改文档比改代码容易漏**：`docs/screens.md`、`design-direction`、`interaction-spec` 三处要同步。
8. **不要把"减负"做成"缩小字号"**：本轮明确不动 17/22/28 的字号。

### 7.2 不要做

- 不要为了填首页/我页的留白加"推荐 / 打卡 / 数据卡 / 广告"。
- 不要把进步页的 PR/部位做回首屏；它们已经决定了去全部数据。
- 不要在训练屏加回"4 段进度条 + 本场摘要 + 第 N 组"；这些都是同义重复。
- 不要把总结页 5 张卡改成 5 个"更小的卡"；要合并成 1–2 块。
- 不要把页边距 24 又改回 20；不要在每个屏单独微调边距。
- 不要用 12 号字去换空间；12 只做标签。
- 不要为筛选弹层新开页面；用底部 sheet。
- 不要把版本号保留在我页；设置/关于已有位置。
- 不要在本次改动里顺手改颜色、圆角、字体族（那是另一条线）。
