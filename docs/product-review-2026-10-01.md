## 二、该加的（逐条说清依据）

### ➕1 训练中断不丢状态（我最想先做的一件）

**场景**：健身房里，你正练着，微信来了、或者接个电话、或者系统把 App 杀了。
回来后如果"刚才那组没了 / 计时归零 / 又回到首页"，那天基本就废了 ——
而**首练完成率与 D7 最怕的就是这种中断**。

**现状**：组记录落库是可靠的（有 `local_store_contract_test` 等钉着），
但**休息计时是内存态**、训练中的"当前动作/第几组"也在内存里（屏幕旋转/页面重建会重置）。
写进 `your-todo` 的那条"真机 Doze 后台"担忧是同一类问题。

**做**：把训练会话（当前动作、第几组、休息开始时刻）落库；计时按 **wall-clock** 算
（`restEndsAtMs - now`），App 回来时自己算差，而不是靠内存里的 tick。
**验收**：杀进程重开 → 回到训练屏、第几组与剩余休息时间正确。

**成本**：2–3 人日 + 新测试（"杀进程"这类测试用 `LocalStore` 重开库来模拟）。
**风险**：极低（不改界面），但会动训练屏的状态管理 —— 需要回归那 22 项训练屏测试。

### ➕2 "今天不想练"的 5 分钟轻量路径

**为什么**：习惯养成的敌人是"全有或全无"。今天没力气做 5 组深蹲，不等于该断掉。
给一条"5 分钟活动"（拉伸/开合跳/平板支撑，现成动作库里有 `time` 类型）——
**让它也算一次训练**，连续记录不断。

**打哪个指标**：首练完成率（门槛更低）与 D7（断签率下降）。
**成本**：1–2 人日（复用选动作 + 计时屏 + 总结页；`workout_type` 加一个轻量标记）。
**风险**：不能让它污染"容量/PR"的统计口径 —— 需要在总结与进步页区分"活动"与"训练"，
否则数据会失真（这是我唯一担心的点，做的时候要用测试钉住）。

### ➕3 完成后立刻给"下一次"

**现状**：总结页给了容量/时长/组数 + 拉伸建议（很好）；但"明天练什么"要回到首页才看得到。
**做**：总结页底部加一行「明天：胸 + 三头（为什么：今天练了背）」+（可选）本地通知提醒。
**打哪个指标**：D7（回访钩子前置）、建议采纳率。
**成本**：0.5–1 人日（引擎已经有了，`today_planner` 直接调；通知要一个新权限 —— 可以后置）。
**风险**：低。通知要单独做"必要性"评估（多一个权限就多一份隐私面）。

## 三、该收的（能藏就藏，不删）

### ➖1 「全部数据」的双维度默认收一个

`全部数据` 页首屏是「按动作 / 按时间」两个分段 + 一个动作选择器 + 五行历史最佳 + 两张趋势图
（截图 `docs/images/ux-review-2026-10-01/06-all-data-zero-lines.png`）。
老手要看，新手**看不懂也不该在这里花时间**。建议默认「按动作」，
把「按时间」收进右上角的"更多"里 —— 少一个决策点。

### ➖2 首页两条次要入口随状态变化 ✅ **已落地（v1.40.0，走的是"备选形态"）**

**修正一处前提（2026-10-04 核代码时发现）**：这里原先写"首页现在**固定两条**"—— **不准**。
「不知道怎么练？帮我定个计划 ›」从 v1.1.0 起就是 `_goalWire == null ? … : null`
（`main.dart`，**没定过计划才显示**），当时就已经是条件显示；真正"固定"的只有
「看看今天练什么 ›」那一条。原始判断（对老手等价于"开始训练"，不必再点）本身成立。

**后来发生了什么**：v1.38.0 把首页中间那块空白换成了**「今天的安排」卡**
（动作 + 建议重量 × 次数 + 「换一批」）—— 于是那条链接与那张卡成了**同一件事的两个入口**，
而这里给的备选形态恰恰就是"（**或换成'换一批'**）"，「换一批」已经在卡上了。

**所以 v1.40.0 的落法是**：删掉「看看今天练什么 ›」那一行，**「今天的安排」卡整块可点**进建议卡
（「我自己选 / 我的计划」只在建议卡里，所以入口不能真删，只换成更大的触摸目标）；
卡上留 `›` 让"可点"看得出来；计划为空时卡片照常显示（入口不因一次加载失败消失）。
**"随状态显隐"这一条仍然不做** —— 删的是一行文字、对所有用户一视同仁，判据里没有状态。

### ➖3 埋点的"给谁看"对账

现在发 18 类事件、7 个公共字段。**我建议做一次对账**：每个事件/字段后面写一句
"谁会用它、用来回答什么问题"。写不出用途的**先不删、先标记**，等有数据再砍。
理由：埋点是**隐私面**，也是政策与两张商店表单的来源；少一个没人看的字段，
就少一处要解释、要披露、要维护的东西。

## 四、明确**不建议做**的（有人会提，但我们有理由拒绝）

| 提议 | 为什么不 |
|---|---|
| 社交 / 排行榜 / 社区 | 与"数据只在本机"直接冲突；审核与运营成本高；北极星是"自己练的人" |
| 饮食 / 卡路里 | 一期就明确不做（`PRODUCT.md` §7）；它会把产品拖向"减脂工具" |
| Apple Watch 独立 App | 原生工作量巨大（我们已经把"不做手表 App"写进 `tech-decisions.md`） |
| AI 聊天教练 | 在 P2 之前不做：它要服务端算力，会破坏"数据不出设备"这条卖点（见 `monetization-plan.md`） |
| 会员页占位入口 | 还没有付费功能之前，占位入口比没有更糟（`profile_screen.dart` 顶部注释里记过这条） |

## 五、我建议的下一版（v1.35.0）就做这三件

1. **训练中断不丢状态**（可靠性，D7 影响最大）；
2. **5 分钟轻量路径**（提升首练完成率，最低成本）；
3. **总结页给"下一次"**（回访钩子前置）。

三件都是**小改动、可回归**，加起来 4–6 人日，而且**不引入新权限、不新增埋点、
不改隐私姿态**。做完之后：门禁全绿 + 真机重装 + 走查一次，照老规矩来。
