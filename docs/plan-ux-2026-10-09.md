## 一、逐条

### 第 1 条 · 未结束的训练跨天还在吗，有没有更好的方案

**现状**：首页那条「上次的训练还没结束 · 上次练到第 N/M 个动作」来自 `active_session`
（冷启动读一次），**现在是不限期保留**的 —— 不区分哪天、也不区分多久以前。

**做法**（照他选的）：跨天之后（即那条会话的 `started_at` 不是今天）弹一次三选一：
**继续 / 结束并保存 / 丢弃**；超过 **7 天**不再弹，只在「计划」页留一条入口（不骚扰）。

✅ **已完成**（2026-10-09）：规则写成一份**纯函数**（`features/workout/stale_session.dart`
的 `staleSessionKind` / `sessionAgeDays` / `staleSessionResumeLabel`）：
* **按自然日算**，不按 24 小时 —— 昨晚 23:50 开始的、今天 00:10 打开 App，**算跨天**
  （用 `Duration.inDays` 会算成 0 天，而用户明明过了一夜；夏令时那两天也会错）。
* 今天开始的**什么都不弹**（用户可能只是切出去接了个电话）；跨天且 ≤ 7 天弹一次；
  **第 8 天起不再弹**。
* 弹层三个出口各自会发生什么，现场就说清：**继续**（走原来的恢复路径，同一批动作、
  同一份进度）／**结束并保存**（写结束时间 = 最后一组的时刻，时长**不会**变成"跨了 8 天"，
  组一条不删 —— 与正常练完是同一件事）／**丢弃**（这次记的组**软删除**进回收站，
  能找回）。关掉弹层 = 什么都不做，入口还在，不替他做决定。
* **首页**：超过 7 天的那条**不再摆**（"一条两周前的半截训练顶在首屏喊接着练"
  正是截图里那个东西）；首页与计划页那行小字都由 `staleSessionResumeLabel` 拼，
  带上了「· 3 天前」。
* **计划页**：入口一直在，且**点它也会弹三选一**（不是直接跳进一个 9 天前的会话）。
* 测试：`test/stale_session_test.dart` —— 纯函数边界（今天/昨天/第 7 天/第 8 天、
  20 分钟但跨天）6 条，加上**把整个 App 装起来**（注入内存库）跑一遍的 6 条
  （弹层文案、三个出口各自在库里留下什么、今天不弹、8 天不弹且首页不摆而计划页有）。

### 第 2a 条 · 整个 App 的 UI 全部改成玻璃质感，配色不变

**现状**：只有 iOS 的底栏 / 分段控件是**真玻璃**（原生 `UIGlassEffect`）；卡片是不透明深色。

**做法**（照他选的）：**顶栏 + 底栏 + 浮层**（弹层、表单、Toast）做玻璃；列表卡片不动。
理由写在这儿：卡片里是小字与图表，玻璃底会让健身房里（暗光 + 汗手）的可读性变差。

### 第 2b 条 · 底栏中间那个图标太割裂

**现状**：中间是"凸起实心圆 + 深色图标"，左右四个是线性图标 —— 两套视觉语言。

**做法**：**去掉实心圆的填充**，中间图标与其余四个同粗细，只靠**尺寸**与一点强调色区分。

### 第 4 条 · 进步页与「我的 → 训练统计」重复度太高

**现状**：两边都是 **2026-10-05 同一批**加的四张同款统计卡（进步：区间容量 / 训练次数 /
总组数 / 个人纪录；我的：训练次数 / 连续天数 / 总组数 / 总容量）—— 三项重名。

**做法**：分工写死 —— **进步页 = 周期对比**（周/月/年 + 趋势 + 个人纪录）；
**我的 = 累计总量**（训练次数 / 总组数 / 总容量）+ **连续天数**。
把重名的那两项从「我的」拿掉（它留"累计"口径，进步页留"周期"口径）。

✅ **已完成**（2026-10-09）：两处都改了，具体是 ——
* **进步页**：四张卡里前三张（容量 / 训练 / 组数）下面那一行**不再是静态的口径说明**
  （原来写的是「最近 7 天」，那是复述区间选择器），改成**与紧挨着的上一个同等长度窗口比**
  出来的变化：`较上期 +12%` / `与上期持平` / `上期没练`（上期是 0 时**不给百分比** ——
  除零；硬写 `+100%` 是编一个数）。纯函数 `previousRangeWindow` / `periodDeltaLabel`
  在 `progress_data.dart`，⚠️ **上一个窗口与当前窗口严格等长且紧挨着**，
  不做"上一个自然周"（口径不一致时百分比是假的）。卡片标题也带上区间名
  （本周容量 / 本周训练 / 本周组数）。
* **「我的」页**：把重名的两张卡（训练次数、总组数）**拿掉**，只留「连续天数 + 累计容量」。
  ⚠️ 那两个**累计**数字没有消失 —— 它们就在上面那张「我的进度」里
  （Lv 那一行右边是「N 次」`profile-level-count`，经验条那一行右边是「N 组」`experience-sets`）。
  同一个数字在同一页出现两遍，才是这一条要治的东西。「总容量」标签顺手改成「累计容量」，
  与进步页的「本周容量」对看时口径写在脸上。
* 测试：`progress_range_test` 新增周期对比的纯函数自测（等长/紧挨着/四种文案），
  `progress_test` 新增两条界面断言（+100% 那条、以及"上期没练"不许编百分比）；
  `profile_test` / `profile_structure_test` / 集成测试里按旧 key 的断言都跟着改了。

### 第 5 条 · 「我的」最下面那行解释性语言有必要吗

（没配备份地址的包是另一句：`…数据只存在这台设备上，不上传任何人。`）

**做法**：**只留「版本 X」**。隐私那半句删掉 —— 它在「我 → 隐私与关于」、两道同意门
和隐私政策正文里都说过，写在页脚像小字免责声明。
⚠️ 连带：那句是**配置相关**的（配了备份服务器就不能说"不上传"），删掉之后
`profile_screen.dart` 里那条注释与守着它的测试要一起改（否则留一条永远为真的空规则）。

✅ **已完成**（2026-10-09）：页脚只剩 `版本 $kAppVersion`；顺带删掉只给它用的局部变量
`cloudOn` 与随之失效的 `backup_config` import（`dart analyze --fatal-infos` 会抓这种"算了没人用"）。
那条"配置相关"的**去向**承诺没有消失，它改由**设置首页**那句顶着
（`settings_home_screen.dart`：配了地址 →「唯一会联网的是匿名统计与你自己开的云备份」，

⚠️ **顺手修掉一份过期很久的集成测试**：`integration_test/cloud_entry_gate_test.dart` 还在

它只有人手动跑、门禁里不跑，所以过期了没人发现。现在改成：我的 → 顶栏齿轮 → 看那句实话 →
进「数据与备份」找入口。

### 第 6 条 · 「今天的安排」要能长按拖动调整顺序 / 删除 / 替换动作

**现状**：那份安排是 **`planToday` 每次算出来的**（`widget.todayPlan`），**不落库** ——
所以"改了它"目前无处可存。

**做法**：先把当天这份**落库**（新表 `day_plan`），拖动 / 删除 / 替换才存得住；
「开始训练」时按它建会话。顺序：先落库 + 读写，再上长按拖动的手势。

✅ **已完成**（2026-10-09）：
* **落库**（这一批的 v27 那次迁移）：`day_plan_item`（date + position + 动作 + 处方）与
  `day_plan_day`（"这一天排过了"的标记）。**为什么两张表**：用户可以把今天的动作
  **全删光**，而"我删光了"必须存得住 —— 只按"有没有行"判断的话，下次冷启动那批动作
  又冒出来，他会以为删除按钮是坏的。存的是**动作 + 处方 + 顺序**，
  引擎给的 `Suggestion` / `LastSession` 刻意不存（那是每次打开现算的）。
* **以库里那份为准**：`_loadTodayPlan()` 先看今天有没有存过 → 有就用它
  （用 `TodayPlanner.planFromRoutine` 把 id + 处方还原成完整计划），没有才按分化现算
  **并落库**。`换一批` 与新加的"重新生成"都会写回库（否则那是个假按钮）。
  顺手清掉 30 天前的死数据（一天几行，只有当天那份有用）。
* **长按拖动 / 替换 / 删除**：长按首页那一行 → 弹层
  （`features/today/day_plan_editor.dart`）。**为什么放弹层而不是就地拖**：
  首页整块是一条滚动列表里的卡片，就地拖动会与"上下滚页面"抢同一个手势
  （真机上"想滚一下却把动作拖走了"比"少一步"更糟）。弹层里长按任意一行即可拖动
  （`ReorderableDelayedDragStartListener`），每行一个「换一个」与一个「删掉」。
  ⚠️ 弹层**必须 `enableDrag: false`**：BottomSheet 自带的下滑关弹层会先赢下手势竞技场，
  症状是"按住一行往上推，整个弹层被拖下去了、顺序一点没变"（测试当场抓到）。
  替换走动作选择器并**按这个动作的部位预筛**，且**沿用原来那一格的处方**
  （换的是动作，不是重新定计划）；全删光是允许的，弹层会如实说"都删光了"并指出
  `换一批` 那条出路。
* **可见性**：卡片底部加了一句「长按调整顺序 / 换动作 / 删掉」——
  一个只有长按才知道的入口等于没有。
* 测试：`test/day_plan_test.dart` 16 条（仓库 7 条 + 编辑器 5 条 + 整个 App 4 条），
  其中**真的做了一遍长按拖动**（手势节奏、起点都要对，见测试里的注释）；
  `delete_all_test` 的表清单守门与逐表核行数都加上了这两张表。

### 第 7 条 · 按肌群细分搜动作（上胸、中缝…）

**现状**：动作库只有大部位（胸/背/腿/肩/手臂）+ 别名搜索。

**做法**：给动作加**细分标签**（上胸 / 中缝 / 下胸 / 三角肌后束 …），搜索与筛选都能用；
标签由我按动作名 + 说明来标（351 个动作，先覆盖常见的那批）。

✅ **已完成**（2026-10-09）：
* **词表**（每块肌肉下面几个说法，写在 `seed/build.mjs` 的 `SUB_TAGS` 与
  `app/lib/core/labels.dart` 的 `kSubTagsByMuscle`）：胸=上胸/下胸/中缝 ·
  背=背阔/上背/下背/斜方 · 肩=前束/中束/后束 · 手臂=肱二头/肱三头/前臂 ·
  腿=股四头/腘绳/臀/小腿/内收 · 核心=上腹/下腹/侧腹。
* **打标**：按**名字 + 别名**的规则一次性打上（如"上斜"→上胸、"夹胸/飞鸟"→中缝、
  "侧平举"→中束、"提踵"→小腿），**不拿说明当分类依据**（散文做分类会写出不可复现的规则）。
  覆盖 **230/318 个力量动作**；没标到的（如"杠铃卧推"）**保持空** ——
  标签是内容债，**宁可没有也不猜**，猜错的筛选比没有筛选更糟。
* **校验**（`seed/build.mjs`）：标签必须是数组、非空、**属于自己的主部位**、不重复、
  只给 strength 动作；构建时打印覆盖率。⚠️ 另有**交叉检查**：客户端那份词表少一个标签就报错
  （否则"chip 点下去筛不到任何动作，而门禁全绿"）。这条检查自己也反向验证过 ——
  把 Dart 里某个标签改坏一个字，种子构建当场红。
* **搜索与筛选**：选择器里选了部位才出现那一行细分 chip（"全部 / 上胸 / 下胸 / 中缝"），
  换部位会清掉上一个（不然会出现"背 + 上胸"这种筛不出东西的组合）；
  **搜索框打"上胸"也能搜到** —— 用户要的是"哪些动作练上胸"，不是"名字里带这三个字"；
  行内副标题会显示标签（「胸 · 上胸 · 哑铃」），搜出来的结果看得出来为什么被搜出来。
* **存储**：`exercise.sub_tags`（这一批的 v28 那次迁移，JSON 数组文本，与 `aliases` 同一性质）。
  用户自建的动作永远是 `[]` —— 我们不为他猜。
* 测试：`exercise_repository_test` 新增 7 条（读得进来 / 筛得对 / 标签之间不互相污染 /
  搜索命中 / 与部位器械叠加 / 没标的不被筛出 / 自建动作为空），
  `exercise_picker_test` 新增 5 条（不选部位时不出现 / 换部位换词表 / 点标签筛对了 /
  「全部」退回部位层 / 打字搜索命中）。`docs/data-model.md` 补了词表与三条规矩。

### 第 8a 条 · 加重量的步进能不能自定义

**现状**：步进来自每个动作自己的 `weightIncrement`（如 2.5 lb / 1.25 kg），界面不可改。

**做法**：在训练屏那个调整面板里加"步进"入口：**每个动作单独设 + 一个全局默认**。

✅ **已完成**（2026-10-09）：三处都落地了 ——
* **训练屏**：重量那一行的「±步进」小胶囊可点（`step-weight-edit`），弹层里选档位
  （kg 0.5/1/2/2.5/5，lb 1/2.5/5/10）或自己输一个数，**并且一次问清范围**：
  「只改这个动作」/「所有动作都改」。
* **设置 → 偏好设置**：新增「加重量」一组，与训练屏**共用同一个弹层**
  （`core/weight_step_dialog.dart`）——设置页里不问范围，只有「所有动作都改」
  （"只改默认值"只影响以后新建的动作，摆在设置里就是让人猜）。
* **落库**：动作自己的 `weight_increment`（训练屏改单个动作走这条）+ `user_profile`
  新增 `default_weight_increment`（这一批的 v26 那次迁移，`null` = 没设过）；「所有动作都改」
  两处都写。⚠️ **自重动作（`weight_increment == 0`）跳过**，回收站里的也跳过。
* **新建自定义动作按用户那个值开场**（自重除外），没设过才按器械猜。
* ⚠️ **顺手修掉两个单位 bug**（写这一条时踩到的）：弹层里的档位念的是**显示单位**，
  而库里的重量永远是 kg —— 1) lb 用户点「5」曾经会被存成 **5 kg**（他以为是 5 lb，
  界面上会变成 +11 lb）；2) 步进的数字原来跟着别处 `round1` 舍到一位小数，
  用户输进去的 1.25 会显示成 1.3。现在落库前统一过 `toStoredKg`，显示走新的
  `formatStep`（kg 原样、lb 换算后保留一位）。两条都有测试钉着。

### 第 9 条 · 健康库里还有哪些数据能接

**现状**：只读体重 / 体脂率 / 身高（详见 `docs/plan-health-sync.md`）。

**做法**：**先接腰围**（与现有三类同属体成分、共用同一次单独同意，政策只需改几处）；
