# 徽章体系重设计 + 留存玩法（2026-10-06 用户拍板）

> **这份文档就是这一批的施工图**：用户看完成品后逐条点了头 ——
> ① A1–A5 全做；② 徽章从 13 枚扩到 **70~80 枚**；③ 下面第二部分 **9 条全做**。
> 进度写在文件末尾的清单里；**没打勾的不许当成做完了**。

## 三条红线（写给下一个人，也是写给"未来的我"）

1. **不引入公开社交上传**（不分享到平台、不上传成绩到任何公开位置）——
   ⚠️ **2026-10-10 修订**：这一条原本还写着"不加好友"，而用户当天拍板"健身搭子很必要、要做"，
   于是 **1:1 搭子（好友关系）不再属于这条红线**（它是一对一、用户主动选范围、无公开内容）。
   搭子的边界与方案见 `docs/plan-social-2026-10-10.md`；**社区/排行榜/公开动态仍然不做**；
2. **不发虚拟货币、不做抽卡/随机奖励**（那套一旦进来，这个 App 的性质就变了）；
3. **不新增权限、不新增埋点字段**（政策、商店表单、隐私事实表一个字都不用改）。

另外沿用仓库既有底线：**徽章全部算出来、不落库**（存一份解锁状态就会和训练记录不一致 ——
改历史、导入备份、跨时区、换设备恢复都会露馅）。唯一的例外是"解锁过"这件事本身：
它**复用现有的 `app_notification` 表**（解锁那一刻本来就会写一条通知），不新增表。

## 一、徽章体系（A1–A5）

### A1 · 分类收集线 + 集齐奖励（展示性）

* 四条收集线（沿用现有 `BadgeCategory`）：连续打卡 / 力量突破 / 探索发现 / 里程碑。
* 每条线在成就页显示**线进度**（"力量 7/18"）。
* **集齐一条线**给一个**展示性**奖励 —— 只做看得见的东西：
  * 成就页顶部该线的**主题色 + 线徽记**点亮；
  * 「我」页段位卡边框换成该线的颜色；
  * **不做**解锁皮肤商城、不做可消费道具。
* 奖励状态同样是**算出来的**（该线是否全解锁），不落库。

### A2 · 「离你最近的一枚」

* 成就页顶部固定一块：**当前差得最少、且未解锁**的那一枚（差 0 的不算，那是已解锁）。
* 展示：徽章 + "还差 N 次 / N kg / N 天" + 一句"今天做 X 就能拿到"。
* 判据纯函数：`nearestBadge(statuses)` —— 按**剩余比例**（而不是绝对值）排序，
  否则"还差 94536 kg"这种会被误判成"最近"。
* 位置：成就页顶部（在计数行下面），点它不跳走（与首页那块"今天的安排"同一条纪律：不给假入口）。

### A3 · 每周挑战（限时、过期作废）

* 每周一枚，**由周序号纯函数推导**（`weeklyChallenge(weekIndex)`），不落库：
  同一周内所有人看到的是同一枚，跨周自动换。
* 候选池：从徽章表里挑"可在一周内达成"的那些（例：本周完成 3 次上肢 / 本周练满 4 天 /
  本周任意一次单组 ≥ 8 次……），按周序号取模选一枚。
* 判定：只统计**本周内**的训练记录（用现有 `SetRecord.loggedAtMs` + 周起止）。
* 过期：上周的挑战**不补**、不留痕（这是稀缺感的来源）；成就页只显示当周那一枚 + 剩余天数。
* 拿到后进**通知**（复用现有 `NotificationKind.achievement`，不新增枚举值）。

### A4 · 隐藏徽章

* 一小撮徽章的 `how` 在**解锁前**显示为"？？？"（名字仍是可见的，否则用户不知道有这回事）。
* 解锁后才显示条件与说明（实现上就是 `BadgeStatus.hidden` 标记 + 展示层分支）。
* 放「探索发现」线（例：凌晨练、连续两天同一动作、只用自重练满一次……）。

### A5 · 段位（徽章总数映射）

* `rankFor(unlockedCount)` → 段位名（青铜 / 白银 / 黄金 / 铂金 / 钻石 / 大师），
  阈值写在一个常量表里、可单测。
* 挂在「我」页：一条进度（还差 N 枚到下一段）+ 当前段位；
  与 A1 的线奖励联动（集齐一条线 → 那张卡换该线颜色）。

## 二、徽章种类：13 → 70~80 枚

**扩法**：四条线各 ~18–20 枚，全部由**现有数据**算得出来（`SetRecord` / 动作库 / 身体数据 /
日期），**不新增表、不新增埋点**。分批做，每批都要有单测（判据纯函数在 `badges.dart`）。

| 线 | 大致覆盖 |
|---|---|
| 连续打卡 | 首训、3/7/14/30/60/100/365 天、断签后回归、早鸟、夜猫、周末战士、一周全勤、月度铁人…… |
| 力量突破 | 单次 1/5/10/20 吨、累计 10/50/100/500 吨、百公斤俱乐部、体重倍数（卧推 0.75×/1×/1.5×）、PR 次数（1/10/50/100）、单动作 100 组…… |
| 探索发现 | 10/20/50/80/120 个动作、每个主部位都练过、自由重量/器械/自重各 20 次、新动作 10 次、隐藏那几枚…… |
| 里程碑 | 练满 10/50/100/300/500 次、总组数 500/2000/5000、单次 20/30/40 组、单次 60 分钟、连续 4 周每周 ≥3 练…… |

工程注意：
* `BadgeStatus` 已有 `current/target`，**新增徽章只要给判据**；
* 判据一律写成**纯函数 + 单测**（`badges.dart` 只做计算，`achievements_screen.dart` 只做画）；
* 成就页要能撑住 70+ 枚：按线分区 + **每区两行折叠**（"展开全部"），别一次铺满 3000px；
* 稀有度按"难度"真实定档（不许为了好看全给 epic）。

## 三、第二部分：9 条留存玩法（全做）

| # | 玩法 | 复用/新增 | 落点 |
|---|---|---|---|
| 1 | **周报 / 月报** | 复用现有分享卡与统计 | 每周一进首页时一张可分享的总结卡（本地生成，不上传） |
| 2 | **连续保护（补签）** | 复用 `streak.dart` | 每周一次：代价 = 本周至少练过 1 次；补签不涨连续天数，只防断 |
| 3 | **每周挑战 / 赛季** | 与 A3 同一套实现 | 成就页 + 首页一行入口（一处实现两处用） |
| 4 | **PR 墙** | 复用 `all_data.dart` 的最佳记录 | 「进步」页或成就页：每个动作的历史最佳 + 上次破纪录距今 |
| 5 | **部位平衡提示** | 复用引擎的部位轮转 | 首页一行："这周胸 3 次、腿 0 次" |
| 6 | **固定训练时段** | 复用 `reminder_service` | 若历史上某时段练得最多 → 一句"要不要定在 19:30" |
| 7 | **轻量等级 / 经验** | 新增纯函数 | 「我」页一条进度（总容量或总组数映射），不加货币 |
| 8 | **练后小知识** | 新增内置文案表（不联网） | 总结屏之后一条 15 秒读完的小知识 |
| 9 | **回归激励** | 复用「5 分钟活动」 | 连续 7 天没练 → 首页那条轻量入口置顶并换文案 |

红线复核：以上 9 条**都不需要联网、不新增权限、不新增埋点字段**；
分享（第 1 条）沿用现有"生成图片/文本落到剪贴板"的做法，**不上传到任何平台**。
