# 练了么 · UI/UX 概念重设计（2026-11-13）

> **用户原话**：「都不好 只保留配色 ui和ux给我大改吧」
>
> 解读：
> - **保留**：现有暖黑 + 橙色配色（`#090706` / `#E2663A` 及相关中性色）。
> - **允许大改**：UI 与 UX —— 导航、信息架构、页面结构、交互模型都可以重新想。
> - **不是**：继续调字号、换卡片、再做一版 A/B。上一轮 A/B 被否，不是因为哪一版不够大，
>   是因为它们仍是**同一套「顶栏 + 内容块 + 底部 3 Tab」版式**的两种字号/容器变体。
>
> 这一轮做**概念级**探索：3 个互不相似的方向，各给一句概念、导航模型、首页骨架、
> 「记一组」的交互模型、训练屏、进步屏、记忆点、数据兼容、实现代价与风险。
>
> **边界**：只写 `docs/redesign-concepts-2026-11-13.md` 与 `prototype/concepts/`；
> 不改 `app/`、不动 `dist/`、不 push、不重出商店截图。

## 0. 三个方向一页看

| | 1 仪表盘 · Cockpit | 2 会话流 · Session stream | 3 纯粹工具 · Pure tool |
| --- | --- | --- | --- |
| 一句概念 | 把训练当实时仪表：状态灯、大数字、一个键 | 今天是一张日程，训练是一段进行中的会话 | 一屏只做一件事：一个巨大的开始/记录表面 |

| 推荐 | 备选（身份强，密度风险） | **推荐** | 最激进备选（UI 最纯，UX 风险最高） |

## 1. 锁定 / 可改范围

| 范围 | 锁定 / 可改 |
| --- | --- |
| 核心循环 | **锁定**：打开 → 今天练什么 → 点一下记一组；每组点击数 ≤1；单手、暗光 |
| 数据 | **锁定**：表结构 / 本地数据 / 备份 / 隐私 / 会员 gate / 权限 / 埋点事实不变；会员仍隐藏 |
| 网络 | **锁定**：离线优先，断网也能记；不引入必须联网的页面 |
| 品牌 | **锁定**：产品名「练了么」；暖黑底 + 橙色；不做玻璃 / 彩色氛围光 / 大阴影 |
| 内容取舍 | **保留意图**：信息少而重；首页 ≤2 块；进步首屏 hero + 趋势 + 入口；训练目标进表头；总结小结收起。可以换形式，但不把这些全部塞回来 |
| 导航 / IA / 交互 | **可大改**：3 Tab 不再是锁；可以换导航模型、换首页、换训练屏、换记组手势 |
| 页面结构 / 视觉 | **可大改**：卡片可以消失，标题可以换位置；只保留配色令牌与上面的事实 |

> 为什么 3 Tab 可以动：这一轮用户点名「UX 大改」；但「我/备份/隐私」必须仍然可达。
> 三个方向都给「我」留了明确入口：头像（1/2）或抽屉（3）。

## 2. 现状盘点：不是丑，是缺概念

v2.3.0 已经把「结构减负」做完了：首页 3 行 + 汇总副标题 + 事实行；训练目标进表头；
进步只留 hero/趋势/入口；总结小结收起；我页合并。结构是对的，问题在**视觉与交互仍是同一套模板**：

- 每个主屏都是「顶部标题 + 内容块 + 底部 3 Tab」；
- 主要动作都是「卡片里的橙色药丸按钮」；
- 训练屏是「一张组表 + 一个记录键」；
- 进步屏是「大数字 + 卡片图表」；
- 上一轮 A/B 只改了字号和容器，**没有改用户理解产品的心智模型**，所以看起来都像同一版。

因此这一轮不再在「页」上做文章，而是换三个**产品模型**：

1. **仪表**：训练是一个需要「读数 + 操作」的过程；
2. **会话**：训练是一段有开始、时间、结束的记录；
3. **工具**：训练是一个只有一个按键的器械。

## 3. 方向 1：仪表盘 · Cockpit

### 3.1 一句话

**把训练当实时仪表：当前该做什么用大数字显示，用一个键完成，状态用灯和刻度表达。**

### 3.2 「大气」怎么变成可观察决定

| 维度 | 具体决定 |
| --- | --- |
| 尺度 | 首页仪表环 **Ø206**，环心数字 **56**；训练屏环 **Ø246**，重量 **56**；记录键 **88**；标题 36 |
| 重量 | 环、刻度、等宽数字、硬件感单键；没有卡片边框，信息由刻度与留白分组 |
| 密度 | 仪表区**高密度**（16 个刻度、3 行计划），键周围**低密度**；不是每块都一样松 |
| 节奏 | 一屏三拍：**读数（环）→ 计划（3 行）→ 单键**；训练屏同理：目标 → 环 → 键 |
| 橙色预算 | 只出现在「当前/主键」；完成用 `success` 小灯，PR 用 `pr` 小灯，不铺大面积 |
| 不做 | 不做发光、玻璃、彩色氛围光；仪表靠形与刻度，不靠光 |

### 3.3 导航模型

- 底部 **3 个读数轨道**：`今日 0/16` / `记录 12` / `进步 640`。
- 「开练」不是 Tab，而是页面上的**大键**；训练屏是全屏沉浸，无底栏。
- 「我」从头像进入（本页右上角 32pt 头像）。
- 为什么：仪表盘的价值是「扫一眼读数」，所以每个导航项本身也带读数；主操作留在内容里。

### 3.4 首屏骨架

```
日期 · 周三                              头像
今日训练
上肢 36 / 800
健身房 · 4 动作 · 16 组 · 约 40 分钟
              ┌─────────┐
              │   Ø206  │ 环心 0/16
              │  0/16   │ 16 刻度；橙色起点
              └─────────┘
01 杠铃卧推        4×8–10 · 40 kg
02 哑铃卧推        4×8–10 · 12 kg
03 上斜哑铃卧推    4×8–10 · 10 kg
本周 2 练 · 连续 4 天 · 离线可用
[            开始 · 上肢  72            ]
今日 0/16  |  记录 12  |  进步 640   ← 读数轨道
```

- 首屏 **2 块**：仪表+计划是一块，开始键+事实是一块；底部是控件不是内容块。
- 保留 3 行 + 汇总 + 事实行；没有把第 4 行或更多卡塞回来。

### 3.5 「记一组」的交互模型

- **1 次点击**训练屏底部的 **88pt 单键**。
- 点下后：环的当前段填满 → 当前组序号 +1 → 下一个重量/次数就位 → 组间计时开始。
- 没有弹窗、没有表单、没有确认；`撤销` 以内联 3 秒提示出现（不阻塞）。
- 改重量：点环下方重量数字进入**同屏步进**（不跳页）；换动作：环下方左右箭头。
- 状态灯：4 段环对应 4 组；完成绿点、当前橙段、未来灰段。

### 3.6 训练屏

```
‹ 退出          动作 1 / 4          结束
杠铃卧推 28
目标 4 × 8–10 · 第 1 组
              ┌───────────┐
              │   Ø246    │  40 kg 56
              │   ×8      │  当前组
              └───────────┘
上次 40 kg × 8 · 组间 90 秒
[            ✓ 记录本组  88           ]
‹ 上一个        改重量        哑铃卧推 ›
```

- 无底栏、无卡片；目标在表头，当前组在环心；主动作是单键。
- 完成状态由环段与灯表达，不靠颜色文字。

### 3.7 进步屏

- 仪表化：`640 kg` 作为环心/大数字，趋势作为一条环形或满宽线，入口一条。
- 保持「hero + 趋势 + 入口」；不把部位/PR/最近训练重新铺回首屏。
- 可以把它做成「三个小仪表」：容量 / 连续 / 本周，但首屏只保留 hero + 趋势 + 入口。

### 3.8 记忆点

**一个像驾驶舱的环 + 一个硬件感的单键。** 用户离开后能画出来的是「一个圆环和一个大键」，不是一张卡。

### 3.9 数据兼容

- 使用现有 session / set log；环的段数 = 计划组数；已完成 = 日志条数。
- 不需要新表；状态灯/环是同一份数据的两种画法。
- 离线、备份、隐私、gate、埋点不变；会员不出现在任何首屏。

### 3.10 实现代价与风险

| 项 | 说明 |
| --- | --- |
| 代价 | **中高**：自定义仪表环（CustomPainter/SVG）、底部读数轨道、训练屏沉浸模式；不改表 |
| 风险 1 | 仪表可能变成装饰：必须保证「环心 = 当前组」而不是泛泛进度 |
| 风险 2 | 状态灯/绿/金增加颜色数量；必须限制在小点，不铺面积 |
| 风险 3 | 高密度区在 2.0× 字号下会更挤；环与计划行要能换行/滚动 |
| 适合 | 喜欢「设备感/掌控感」、经常看数字的人 |
| 不适合 | 觉得仪表=游戏化、想要极简的人 |

## 4. 方向 2：会话流 · Session stream

### 4.1 一句话

**今天是一张日程，训练是一段有开始/时间/结束的会话；页面像时间流，不像表单向导。**

### 4.2 「大气」怎么变成可观察决定

| 维度 | 具体决定 |
| --- | --- |
| 尺度 | 页标题 **40**；会话标题 22；当前行 **88**；组间计时 **54**；时间戳 11 |
| 重量 | 一条 **2px 时间轴** 贯穿页面；当前会话是一条完整的横带，不是一张小卡 |
| 密度 | 中密度：每 44–72pt 一个时间节拍；空的时间段保持空，不补卡 |
| 节奏 | 垂直节拍：**时间 → 事件 → 现在行**；训练屏同一根轴，向下生长 |
| 橙色预算 | 只在「现在」与当前行；完成用 `success` 小勾；历史全灰 |
| 不做 | 不做玻璃、发光、大阴影；靠时间轴和空白形成版面 |

### 4.3 导航模型

- 底部 **今天 / 现在 / 日志**：
  - `今天` = 日程；
  - `现在` = 一个**动作 + 状态**胶囊：未开始是「开始 · 上肢」，进行中是「回到会话」；
  - `日志` = 历史/进步。
- 「我」从头像进入。
- 为什么：用户的真实问题是「现在该做什么」，所以「现在」不是一个 Tab，而是**当前会话的状态按钮**；它随会话变化。

### 4.4 首屏骨架

```
11 月 11 日 · 周三                        头像
今天 40 / 800
一天一张日程，训练是一段进行的会话
18:30  ●  今晚 · 计划
          上肢 · 健身房 22
          4 个动作 · 16 组 · 约 40 分钟
          目标 4 × 8–10 · 上次 11/9
20:10  ○  练后拉伸（可跳过）
          ...
最近  11/9 09:10 · 上肢 · 16 组 · 6,480 kg
今天  |  现在 开始 · 上肢  |  日志
```

- 首屏 **2 块**：时间线（含计划会话）是一块，最近一行是一块；中间的空时间是节奏。
- 保留首页 3 行？**不**把 3 行动作塞回首页；动作在会话里展开，首页只给「练什么/多长时间/目标」。
  这是用户允许的「换形式」，不是丢信息；动作清单在打开会话后可见。

### 4.5 「记一组」的交互模型

- **1 次点击**当前会话行右侧的圆点（训练屏底部 88pt 当前行）。
- 点下后：该行立即变成一条带时间戳的日志（`18:41 · 第 4 组 · 40×8`），
  下一行「当前组」从下方出现，组间计时开始。
- 没有弹窗；`撤销` 在最新一条日志上长按/左滑（可选，不占主流程）。
- 这一模型的关键：**记录就是界面的生长**，不是填完表再提交。

### 4.6 训练屏

```
‹ 退出          上肢 · 进行中          结束
杠铃卧推 · 第 4 / 4 组
目标 4×8–10   已练 12:34   本场 3/16 组
18:31  ✓ 第 1 组 40 kg × 8
18:33  ✓ 第 2 组 40 kg × 8
18:36  ✓ 第 3 组 40 kg × 8
            组间休息
             01:28
       ▁▁▁▁▁▁▁▁▁▁
[现在 ● 第 4 组 40 kg × 8        ✓ 88]
点右侧圆点记下这一组 · 不需要弹窗
‹ 上一组        改重量        下一个动作 ›
```

- 目标在表头；会话日志是主内容；当前行是输入面；组间休息是时间轴的一部分。
- 无底栏、无卡片；一条会话轴就是屏幕。

### 4.7 进步屏

- 作为「日志」的顶部：hero（640）+ 趋势 + 入口；下面是按周/月分组的日志。
- 保持「hero + 趋势 + 入口」；不把部位/PR/最近训练塞回首屏。
- 历史数据天然是流；不需要额外图表卡。

### 4.8 记忆点

**一条从 18:30 长到 19:00 的会话列，当前行是一块 88pt 的深色带。**
用户离开后能画出「一条线 + 几个时间 + 一个当前行」。

### 4.9 数据兼容

- 使用现有 session / set log；若已有逐组时间就显示，没有就用会话开始 + 组序推算展示。
- 不改表；不新增云端依赖；断网时当前行照样落本地。
- 备份/隐私/gate/埋点不变；会员不出现。

### 4.10 实现代价与风险

| 项 | 说明 |
| --- | --- |
| 代价 | **中**：会话状态机（idle/active/rest/finish）、时间线组件、导航 `今天/现在/日志`；不改表 |
| 风险 1 | 会话过长时日志滚动；当前行必须始终可达（吸底或自动滚到） |
| 风险 2 | 时间戳若缺失，展示会假；必须用真实会话开始时间或明确「第 N 组」不显示时间 |
| 风险 3 | 从 3 Tab 改为「现在」状态键，老用户需要一次解释；首启引导/文案要写清 |
| 风险 4 | 空白时间线可能被误读为「没内容」；用时间标记和最近一行锚定 |
| 适合 | 把训练当「一段经历/记录」的人；喜欢时间线、日志、低干扰 |
| 不适合 | 想要实时仪表读数、或极简到只有一个键的人 |

## 5. 方向 3：纯粹工具 · Pure tool

### 5.1 一句话

**一屏只做一件事：一个巨大的开始/记录表面；计划、历史、进步、我全部退到抽屉。**

### 5.2 「大气」怎么变成可观察决定

| 维度 | 具体决定 |
| --- | --- |
| 尺度 | 首页/训练主键 **Ø218**；训练数字 **72**；首页标题 **44**；只有 2 个文字层 |
| 重量 | 一个巨大的橙色圆盘 + 黑色空场；没有卡片、没有底栏、没有分割线 |
| 密度 | **极低**：首屏只有一个动作；一次只出现一个决定 |
| 节奏 | 一拍：进入 → 一个大键；训练屏也是一拍：数字 → 大键 |
| 橙色预算 | 整个屏幕只有大键是橙；其他全部灰/黑/白 |
| 不做 | 不加任何导航、卡片、玻璃、阴影、氛围光；空就是空 |

### 5.3 导航模型

- **无常驻导航**。
- 顶部右侧 `≡ 抽屉`；底部一个 **grabber**：上滑打开 `计划 / 记录 / 进步 / 我`。
- 训练时抽屉隐藏，只留「退出 / 结束」。
- 为什么：这个方向的产品主张是「你来这里只做一件事」；导航是第二层，不应出现在首屏。
- 代价：进步/我变成 **2 次操作**（抽屉 → 项目），必须用首启/文案教会；核心「记一组」仍 1 次。

### 5.4 首屏骨架

```
11 月 11 日 · 周三                 ≡ 抽屉

                 今天
                上肢 44 / 800
     健身房 · 4 个动作 · 16 组 · 约 40 分钟
              ┌──────────────┐
              │    Ø218      │
              │    开始      │
              │ 点一下开始训练 │
              └──────────────┘
        上次 11/9 · 16 组 · 6,480 kg
              ▁▁▁▁
     上滑 · 计划 / 记录 / 进步 / 我
```

- 首屏 **1 块**：主表面；事实行与抽屉是辅助，不是内容块。
- 没有 3 行清单；动作清单在抽屉的「计划」里；首页保持一件事。

### 5.5 「记一组」的交互模型

- **1 次点击** Ø218 的「记录」圆盘。
- 点下后：小点前进（4 组中的第 2 个亮起）、重量/次数保持、无弹窗、无确认。
- 改重量：点大数字进入同屏步进（数字下方出现 +/-），不跳页；
  上一个/下一个在底部两侧，用大点击区，不需要精确瞄准。
- 失败恢复：大键上方 3 秒内出现「撤销」；不阻塞下一次点击。

### 5.6 训练屏

```
‹ 退出            杠铃卧推            结束
目标 4 × 8–10 · 第 1 / 4 组

                 当前组
                 40 kg 72
                   × 8
              ┌──────────────┐
              │    Ø218      │
              │    记录       │
              │      ✓       │
              └──────────────┘
                 ● ○ ○ ○
‹ 上一个            改重量            下一个 ›
```

- 无底栏、无卡片；当前重量是页面最大的东西；大键是唯一主动作。
- 单手：大键在拇指区；上一个/下一个在底角但点击区大。

### 5.7 进步屏

- 抽屉 → 进步；进入后仍是「hero 640 + 趋势 + 全部数据入口」。
- 不把进度塞回首页；首屏永远只有一个主任务。

### 5.8 记忆点

**黑底上一个大橙色圆键。** 没有第二个可记住的控件。

### 5.9 数据兼容

- 与现在完全同一套 session/set 数据；只是入口被抽屉包住。
- 不改表、不改备份/隐私/gate/埋点；离线；会员隐藏。
- 抽屉的项目全部映射现有路由，不新增业务页。

### 5.10 实现代价与风险

| 项 | 说明 |
| --- | --- |
| 代价 | **高**：整套导航换成「单主键 + 抽屉」，路由、返回、状态恢复、可发现性全部重做 |
| 风险 1 | 进步/我/计划需要 2 次操作；如果用户找不到，会被认为功能消失 |
| 风险 2 | 没有底栏，用户失去位置感；需要清晰的抽屉 grabber 与返回 |
| 风险 3 | 大圆键在 2.0× 字号/小屏上容易挤压；需要自适应直径与文字 |
| 风险 4 | 暗光下单一大块橙色可能过亮；需要控制亮度/面积 |
| 适合 | 极度讨厌导航/表单、只想「点一下记一组」的单人训练者 |
| 不适合 | 需要频繁切换计划/历史/进步的人；首次使用需要教学 |

## 7. 推荐：会话流

**推荐方向 2「会话流」**，理由：

1. **它换的是心智模型，不是皮肤**：今天=日程、训练=会话、记录=日志；首页、训练、进步可以共用同一根时间轴，和现有「页面 + 卡片」彻底分开。
2. **它最贴合一个人在健身房的真实顺序**：看一眼今天 → 开始/继续一段会话 → 一组一组往下长；当前行就在拇指区，1 次点击，不需要表单。
3. **它对数据的利用最自然**：现有 session/set 日志本来就有顺序与时间；不需要新表，进步天然变成「日志 + hero」。
4. **它的风险可控**：导航仍是 3 个区域（今天/现在/日志），只是把「现在」变成状态键；比「纯粹工具」更容易被现有用户理解，也比「仪表盘」少一层自定义绘图/密度风险。

**备选排序**：

- **仪表盘**第二：身份最强、最适合喜欢设备感的人；但仪表容易装饰化、密度难控。
- **纯粹工具**第三：UI 最纯、最「大气」，但 UX 风险最高（隐藏导航、2 次点击、可发现性）。

**不建议拼接**：把仪表环放进会话流、或在大圆键上加 Tab，会让三种心智模型互相打架。

## 9. 实现代价排序

1. **会话流（中）**：新增会话状态与时间线；导航 3 区域；现有数据直接用；主要风险在滚动/时间戳/引导。
2. **仪表盘（中高）**：自定义环/刻度/读数轨道；训练屏沉浸；主要风险在仪表是否只是装饰、密度与 2.0×。
3. **纯粹工具（高）**：整套导航/路由/返回/抽屉/可发现性；主要风险是用户找不到计划/历史/我，以及大键在 2.0× 下的适配。

如果只选一个先做，推荐会话流：概念变化足够大，但不需要先推翻整个导航。

## 11. 风险总表

| 风险 | 方向 | 缓解 |
| --- | --- | --- |
| 仪表只是装饰 | 仪表盘 | 环心必须是当前组/当前重量，不是泛进度；灯对应真实 set |

### 6.3 刻意保留的差异
1. 训练屏当前行是**深色 surfaceHi 带**，不是原型里的纯黑长条；维持 v2 的卡片边界与 88pt 触区。
2. 「现在」胶囊状态文字由底栏静态标签「现在」承担；iOS 原生 `UITabBar` 无法在格内显示动态“已练时长/组数”，状态信息在今天的会话块与训练屏顶栏给出。
3. 今天页未新增“未知时间条目/练后拉伸”占位：现有数据只支持“今天的会话”，空时间段保持为空。
4. 日志的会话展开列出逐组（时间/重量/次数），没有按“动作分组”重新聚合，避免与全部数据页两套口径。
5. 其他屏只做最小视觉对齐，没有按新时间轴语言重排。
