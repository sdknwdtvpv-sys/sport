## 二、这一轮已经修掉的两条

### 5. 连续天数方框比别人大（我的回归）

v1.57.0 的「A 档重排」把「打卡进度卡」撤了（它复述的就是统计格里的那一格），
但**那句披露不能跟着没**——"连续 12 天"里若有 1 天是补的，不写出来就是假话。

当时的做法是把它塞进「连续天数」那张卡里（`Column` + 一行 11pt 小字）。
后果：**那张卡比同排的「训练次数」高出一行**，于是两张卡不等高——这就是你截图圈出来的那条。

现在的做法（`app/lib/features/profile/profile_screen.dart`）：

* 两张格子**只放数字**（各自一个 `StatTile`），高度自然相等；
* 「其中 N 天是补签」变成**网格下面独立的一行**，**靠右对齐**——视觉上仍然归属右边那格；
* 文案仍然复用 `streakProtectionSuffix()`（与首页一字不差），一个字都没删。

新增测试（`app/test/profile_test.dart`）：**量渲染高度**，同排两张卡必须等高；
并且断言那句披露既不在左格、也不在右格里面（防止有人用"把披露裁掉"换等高）。
> 上一版只断言"文案在不在"，所以这个 bug 从测试里漏过去了——布局类修复必须**量尺寸**。

### 8. 成就页不居中

老代码：`_BadgeTile` **写死 100 宽**，`Wrap(spacing: 12)`，一排三枚 = 3×100 + 2×12 = 324；
而内容宽度是"屏宽 − 左右各 20"（Redmi 上 ≈ 353）。**右边永远差二十几像素**，整排看着往左偏。
写死宽度就是根因：换台手机（更窄的、宽屏的、系统大字号下的）剩多剩少又不一样。

现在（`app/lib/features/progress/achievements_screen.dart`）每一枚的宽度由 `LayoutBuilder`
按**可用宽度反算**：三枚 + 两条间隙 = 正好一整行，左右只剩页面自己的留白。

新增测试（`app/test/achievements_test.dart`）：量几何——`三枚宽 + 两条间隙 == 整行宽`，
第一排最右那枚的右边缘 == 内容区右边缘，且三枚等宽。**又是"量尺寸"而不是"找文案"。**

## 三、待拍板的 7 条（逐条给方案与代价）

### 1 + 6. 右上角：铃铛对齐 + 设置收成一颗齿轮

这两条其实是**同一件事**——右上角那个动作区该长什么样。我们的外壳现在**没有统一顶栏**：
「今天」34pt 大字 + 一行日期 + 铃铛；「我」28pt；「进步」28pt 各自为政。

* **A 档（推荐）：加一条统一顶栏**——左标题、右 `[齿轮][铃铛]` 两枚同规格 40×40 图标，
  五个 tab 都用（`app/lib/main.dart` 的外壳 + 各屏去掉自己那行标题）。
  设置类三组从「我的」页搬进**独立的设置页**（齿轮进），「我的」页只留身份 + 数据 + 成就。
  代价：五屏顶部各让出约 44pt；「我的」页要重排一次；铃铛从此在**每一屏**都点得到
  （现在是"只有首页进得去"，这对通知中心反而是补齐）。
* **B 档（最小改动）：只在「我的」右上角放齿轮**，铃铛顺手对齐一下就收工。
  代价：设置入口仍然只活在「我的」里；"右上角"只是「我的」的右上角。

### 2. 底栏：训练居中 + 与其他四个做区别

现在：`训练 / 进步 / 数据 / 计划 / 我的`（`app/lib/core/app_tab_bar.dart:59`），训练在**最左**。
要挪到正中（`进步 / 数据 / 训练 / 计划 / 我的`）并区分展示。两个子决策：

* **顺序**：训练居中之后，左右各两格。iOS 那层玻璃胶囊是"选中格整片亮"，
  顺序改了不影响它；但 `_tab` 的**下标语义会变**（`main.dart` 里 `_bodyFor(_tab)` 与
  一拍测试按下标断言），这些都要一起改。
* **差异化样式**：① **凸起圆形强调**（中间那颗做成浮起的大圆 + 强调色，像相机键）——
  最像"这一个不一样"，但 iOS 的玻璃分段胶囊会把选中态画在那颗圆**背后**，需要把它排除或叠在上面；
  ② **只做同款变色/加粗**——便宜，但"区别展示"的分量小。**建议 ①**。

> ⚠️ 另有一条旧承诺挂在旁边：底栏在 iOS 走玻璃浮动、**Android "一个像素都不改"**
> （2026-10-06 拍板）。这条清单会**动到 Android 那条通栏**——需要你明确"以新清单为准"。

### 3. 通知详情：弹层 → 整屏页

弹层现在是"贴着底边的一条矮纸"，`mainAxisSize.min` 让它有多矮就多矮，所以"不明显"。
两条路：

* **A（推荐）：改成整屏详情页**（`Navigator.push` + 顶栏返回）。与全 App 其它二级页
  （账号/备份/成就/隐私与关于）**同一套导航语汇**；正文、分类、绝对时间都放得下，
  以后加"去看那条记录"这种去路也有地方。
* **B：保留弹层但加高**（`isScrollControlled` + 拖拽手柄 + 至少 40% 高 + 更暗的遮罩）。
  代价：仍然是一层"临时的纸"，与我们其它二级页不一致。

### 4. 通知文案重写

现在三句都是模板句（`app/lib/features/notifications/notification_rules.dart`）：

| 现在 | 问题 |
|---|---|
| `今天还没练` / `19:30 该提醒你的时候，你还没开始。现在开始也来得及。` | 没有**你的数字**，读完不知道"我今天到底差多少" |
| `云备份已完成` / `训练记录已加密上传。换手机时用恢复码取回。` | 说的是机制，不是"这次传了多少" |
| `本周挑战完成：X` / `X。下周会换一枚新的。` | 还行，但同样的句式连着出现就腻 |

重写口径（**不许变成营销**）：**事实 + 你相关的数字 + 一句去路**，每条都随着真实数据变：

* 提醒：`今天还没练` → `19:30 到点了，今天还没开始。昨天练了 5 组，今天做 3 组也算接上。`
* 备份成功：`云备份已完成` → `刚上传 12 组记录（8.4 KB，密文）。上次是 3 天前。`
* 徽章解锁：`解锁「首训」` → `第 1 次训练就到手。目前 3 / 73 枚，白银差 1 枚。`
* 挑战完成：`本周挑战完成：连续 3 天` → `一周里练了 3 天，达标。下周换一枚新的。`

代价：文案会随数据变，测试要从"断言整句"改成"断言关键数字在不在"（现在断言的是原文）。

### 7. 昵称 + ID（身份感）

现在「我的」页顶部只有一个 28pt 的「我」。要点是**身份**，但那两样东西的性质完全不同：

* **昵称**：纯本地、你自己起、随时改（首启引导里问一次，也可以不填）。
  ⚠️ 不参与云备份的合并键、不上报（埋点不带身份）、**二维码/分享类功能我们不打算做**。
* **ID**：**不能凭空编一个号**——编出来的号既不是账号也不是设备号，是假身份。
  诚实的做法：**登录之后**才显示 ID，取 `account_id`（= SHA-256 账号密钥）的**前 8 位**、
  带分组写成 `A3F9-21C4`，并写明"这是你的账号 ID，用于找回/客服核对"；
  **没登录就不显示 ID**，那一行写"未登录"（去路指向账号页）。
  顺带：段位/徽章那些**要跟着账号走吗**？现在它们算的是本机记录——这一条**不改**。

### 9. 「帮助改进产品」默认打开？

**这条不能照字面做**，理由是它撞上我们自己的对外承诺：

* `docs/privacy-policy.md` 有 **4 处**写着这个开关**默认关闭**，第 97 行甚至写明
  "只有你**主动**到「我 → 隐私与关于 → 帮助改进产品」把它打开，下面这些事件才会产生"；
* 首启同意屏（`privacy_consent_screen.dart:109`）当场写着"它默认是关闭的"；
* 商店表单/收集清单与之一致，`privacy-audit` 与 `check-store-forms` 两道门禁钉着这些措辞。

默认打开 = **把已经承诺过的默认值反过来**（而且统计类默认开在应用商店审核里是敏感项）。
既能拿到数据、又不毁承诺的两条路：

* **A：默认仍然关，但在首启引导里"问一次"**——单独一屏：
  "要不要帮忙改进产品？"下面两句实话（收什么、随时能关）+ `打开` / `先不用` 两个按钮，
  点 `打开` 才算打开。这样"主动"两个字仍然成立，改动最小，隐私政策一个字不用改。
* **B（✅ 2026-10-07 用户拍板）：真把默认改成开。**

#### 拍板 B 之后的**完整改动面**（v1.59.0 那一趟的施工单）

`docs/privacy-facts.json` ↔ `app/lib/data/db.dart` 那一列的默认值 ↔ 中英政策正文
（`tool/privacy-audit.mjs` 第 ⑩之四 那条判据钉着，`--selftest` 里有用例）。
要动的清单：
