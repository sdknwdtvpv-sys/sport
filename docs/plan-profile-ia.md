# 「我」这一屏的信息架构（对齐训记「我的」页分析）

> 2026-10-06。起因：用户看完《训记「我的」页面产品分析报告》（竞品拆解，8 组 30+ 入口）之后说
> **"我们当前的「我的」这一屏太乱了"**，问哪些可以借鉴。
> 这一页只做两件事：**从那份报告里挑出对我们成立的**，以及**把我们这一屏"乱"在哪说清楚**。

## 一、报告里可以用的（逐条：为什么适合我们 / 代价）

| 可借鉴 | 为什么适合我们 | 代价 / 前提 |
|---|---|---|
| **① 分组卡片 + 低频沉底** | 这正是治"乱"的药方：它的做法不是"少放东西"，而是**用语义分组承载密度**，把低频与高危的沉到尾部（我们的「危险动作」分组已经是这个形状） | 纯 IA 调整，不动数据；代价是分组标题本身也占地方，分太细反而更乱（见 §三） |
| **② 破坏性操作红标 + 回收站兜底** | 我们**已经有**：`删除全部数据` 是红字、回收站可恢复。报告把它写成"成本低、信任感高"的范式 —— 这两条别动 | 无 |
| **③ 细粒度同步开关（合并/去重策略做成开关）** | 将来接 Apple Health / Health Connect 时直接抄这个结论：**把"合并当天训练""合并同类项"做成用户可见开关**，能省掉一批"为什么重复了"的客服 | 目前 HealthKit 是"明确不做"（要新增权限）；等做的时候把这条写进那份方案 |
| **④ 数据可携带 + 明示"可以给 AI 助手读"** | 我们已经有 CSV / 备份导出与导入（比它更全：整包备份）；报告点出的是**说法** —— 副标题直说"供外部 Agent 调用"。对我们是零成本差异化：导出的 JSON/CSV 本来就能喂给 LLM，只是我们没这么说 | 一句话文案；但它是一句**对外承诺**，得确保格式稳定（我们已有版本号 `format v4`） |
| **⑤ 合规四件套提前备置** | 我们**更全**：隐私协议 / 收集清单 / 第三方共享清单 / **应用内注销**（今天刚上线）都在。这条是"确认已达标"，不是待办 | 无 |
| ⑥ 内嵌图文教程体系 | 我们靠首启引导 + 空态文案 + 文档；真机上用户卡住时没有"在 App 里查一下"的路 | 要自建内容体系（拍照 + 红框标注），成本不低，**建议先不做** |

## 二、明确**不**抄的（逐条给理由，免得下次重新讨论）

| 不抄 | 理由 |
|---|---|
| 经期记录 / 轻断食 | 不是同一个产品。它们是"把别的 App 塞进来"的留存策略，代价是**首屏认知负担**（报告自己把"男性用户默认看到经期入口"列为问题① ） |
| RM 计算器 / 照片墙 / 备忘录 | ① 1RM 我们已经在 PR 墙里算了（同一件事不留两个入口）；② 照片墙要存用户体型照 —— 我们的定位是"数据只在你手机上"，多存一类敏感数据要多一条披露；③ 备注已经在总结页（`workout.note`） |
| 教练生态（教练记 / 教练发来的训练） | B2B2C，另一门生意；我们现在连付费都还没有 |
| 多端（Watch / Mac）/ 网络节点（自选服务器） | 基建级投入；我们连第二端都没有。**网络节点尤其不要学**：我们自己那台服务器是单一后端，"选节点"会立刻变成一套运维与合规问题 |
| 会员徽章前置 / 好评与分享入口组 | 没有商业化的东西不放"购买转化位"；"好评训记"这类**引导评价**在国内商店是敏感的（报告也把它列进增长组，我们不做这一套） |
| 自助修复工具暴露在主路径（历史体重置 0 / 白屏修复） | 报告自己把它列为问题④（易误触）。真要留，也得收进「关于」的深层 —— 而且它是**故障的遮羞布**，我们的做法是把 bug 修掉 |

## 三、我们这一屏"乱"在哪（对着代码与真机截图，说具体的）

`app/lib/features/profile/profile_screen.dart` 从上到下的顺序是：

```
等级卡（Lv，按训练次数）      ← _levelCard()      :458
段位卡（按已解锁徽章枚数）     ← _rankCard()       :554
「训练统计」四张卡 + 连续天数格子
打卡进度卡（已连续打卡 N 天）  ← _streakCard()     :619
经验卡（累计组数 → 轻量等级）  ← _experienceCard() :506
「成就」→ 我的成就入口
「设置」→ 偏好设置 / 数据与备份 / 隐私与关于
版本行 + 一句"数据默认只在本机"
```

问题不是"东西多"（我们只有 6 组，比训记的 8 组 30+ 入口少得多），而是**同一件事说了四遍**：

1. **一屏四个进度条**：等级（还差 4 次训练升 Lv.2）、段位（还差 1 枚到白银）、
   打卡（再坚持 6 天解锁「一周不断」）、经验（还差 99 组到「上量」）。
   四个都在说"你还差多少"，用户读不出**哪一个才是主线**。
2. **"连续天数"出现两次**：统计卡格里一次（`_streak 天`，:359-360），打卡进度卡里又一次（:391-393）。
3. **三套进度体系并存**（Lv 按次数 / 段位按徽章 / 经验按组数）。文档里把它们写成"刻意并存"
   （`docs/screens.md:376`：两个数在真实记录里会分叉）—— **数据上成立，但界面上没告诉用户
   "看哪个"**：三个并列的大卡，视觉权重一样。

一句话：**不是信息过载，是"主角不明确"**。

## 四、建议的改法（三档，按改动量从小到大）

**A 档（最小，只调 IA，不动数据与算法）**
* 把「等级 / 段位 / 经验」三张卡收进**同一个分组标题**（例如「我的进度」），并把它们压成
  一张卡里的三行 —— 一行一个进度条，读起来是"我练到哪了"的一条线，而不是三个并列的大卡。
* **去掉重复的"连续天数"**：统计格里保留（它是四宫格的一员），把打卡进度卡从统计区里拿掉，
  它的"解锁「一周不断」"目标移到成就页/成就入口的副标题里。
* 效果：进度条从 4 个变 3 个（同一张卡）、连续天数只出现一次、页面少一张卡的高度。

**B 档（A + 定一个主角）**
* 在 A 的基础上**明确主角是「等级 Lv」**（它最直观：按次数，新手升级快），把它做成唯一的
  大卡；段位与经验降成它下面的两行小字。
* 代价：与 `docs/screens.md` 里"段位卡 / 经验卡"的既有描述要对齐改写；徽章那一批的
  A5 拍板（段位是徽章总数的映射）仍然成立，只是展示层级降了一档。

**C 档（重排整页，含"收纳进次级页"）**
* 把统计四宫格也收进次级页（「我的数据」），「我」页只留：进度一条线 + 成就入口 + 设置三入口。
* 代价：这一页会变得很空，而"我练了多少"是这个 Tab 的高频诉求（改版前的教训：
  `docs/screens.md:386` 记着用户说过"我里面现在有些复杂能否有些收纳进次级页面？"，
  但当时收的是导出/导入/删除 —— 统计**没收**）。**建议不做**，除非真机上再确认一次。

**推荐 A**（治"乱"的部分基本都在 A 里，且不动任何数据口径），B 等你点头。

## 五、顺带记下的两条"从报告里学到、但先动手会后悔"的

* **不要为了"显得丰富"而堆料**：训记那一屏 30+ 入口是**长期迭代 + 有付费与生态**才撑得住的；
  他们的报告里自己承认了两条问题（经期默认展示、30+ 入口无搜索）。
  我们的原则（`PRODUCT.md`：能自动就不问 / less is more）在这里更值钱。
* **任何"新增入口"都要先问**：它能不能让"第一次训练"更快发生？不能的，一期都不做。
  所以上面四条"可借鉴"里真正落到**改动**的只有 ④（导出那句说法），其余是"等做到那一步再说"。

* "同一个数只渲染一次"的判据（可机械核）：
  `grep -n "连续天数" app/lib/features/profile/profile_screen.dart` 现在有 **3 处** ——
  两处是注释（:86 / :213），**第 :359 才是那格统计卡**；而「已连续打卡」那句在
  `_streakCard()`（:619 起）里又渲染了一次。**A 档做完之后应当是：`连续天数` 只剩统计卡那一处，
  `已连续打卡` 归 0**（补签那句「（其中 N 天是补签）」跟着搬到统计卡那格里，别丢掉 ——
  `profile-streak-label` 那个 key 有测试盯着）。
