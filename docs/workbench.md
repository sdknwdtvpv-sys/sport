# 练了么 · 工作台（一站式看现状）

> 一句话：**"现在到底什么状态"由这一页回答** —— 不用再翻六七个文件，更不用怕翻到的是过期的。
>
> ```bash
> node tool/workbench.mjs --serve          # → http://127.0.0.1:3081/   （推荐，每次刷新当场重新采集）
> node tool/workbench.mjs                  # 命令行快照（几秒，只打摘要）
> node tool/workbench.mjs --json           # 机器可读
> node tool/workbench.mjs --out w.html     # 落一个自包含 HTML（单文件，可直接发给别人看）
> ```
>
> 另有三个可选参数：`--port 3081`（换端口）、`--data <目录>`（换埋点数据目录）、`--root <目录>`（换仓库根）。

## 二、三条刻意的约束（都不是技术限制，是产品判断）

1. **只监听 `127.0.0.1`，只读本机文件，不联网、不上传、没有鉴权。**
   它看的是你自己的开发机。把开发机的东西暴露到局域网上不是"方便"，是事故 ——
   所以**没有** `--host` 这种选项，也不打算加。
2. **默认只跑"快守卫"（十几秒内出结果的那批）。**
   六层门禁要十几分钟，放进页面刷新路径上会让这一页变得没人愿意开。
   门禁有自己的按钮：点一下后台跑，输出实时贴出来，跑完刷页面看"对账"那一栏。
3. **这一页永远不改仓库里任何文件。**
   唯一的例外是你自己指定的 `--out w.html`。清单上的勾选**只写进这个浏览器的 localStorage**
   （键 `lianleme.wb.checks`），服务端**没有**任何写文件的接口 —— 这一条由自检钉着：
   `createWorkbenchServer` 那段里出现 `writeFileSync` / `appendFileSync` / `createWriteStream` 就当场变红。
   页面上也把这件事写在清单旁边，因为"勾了 ≠ 改了文档"这件事必须让人一眼看到。

> 为什么把第 3 条看这么重：如果勾选会写回文档，那么"页面显示的样子"和"文档实际的样子"
> 就有两个事实源，而**过期状态比没有状态更坏**。只读 + 本地记住，是唯一不会产生第二个事实源的做法。

## 三、埋点怎么才有**真实**数据（现在还没有）

现状要说清楚：**后端没部署，所以一个真实用户的事件都没有**。看板上那 3 条是仓库自带的样例
（`server/data/events-2026-09-29.jsonl`），只用来证明"口径算得出来"。

两条路：

| 路 | 怎么做 | 代价 |
|---|---|---|
| **① 部署收集端** | 按 `server/deploy/README.md` 把 `server/collector.mjs` 跑起来（自带 systemd 单元 + Caddyfile），客户端配上报地址 | 需要一台服务器 + 域名/证书；隐私政策 §3.2 已按"默认关、可关"写好 |
| **② 从真机导出** | App 里「我 → 隐私与关于 → 导出统计事件」把本机攒的事件导成 jsonl，放进一个目录，再 `node tool/workbench.mjs --data 那个目录` | 只能看**导出过的那几台设备**；好处是完全离线、后台不需要存在 |

> ②这条路**今天就能用**：它是唯一一条"不部署任何东西也能看到真实埋点"的路。
> 工作台里两种数据一眼可分（看埋点那张卡的标签），不会被误当成线上数据。

### 那四格线上业务指标，为什么现在一个数都不写

日活、次日留存、崩溃率、同步失败率 —— 这四格**刻意永远只有占位**：
`⊘ 待接入` + 一行"还需要什么" + 一个可展开的"为什么算不出来"。

理由很直接：**这四个数是最容易被拿来"感觉一下"的数**（"日活大概几十吧""崩溃率应该不高"），
而一个会撒谎的看板比没有看板更坏。自检里有四条硬断言钉着它：

* 四格必须**全部**是 `⊘ 待接入`；
* 整张卡里**不许出现 `%`**（画了百分比就是撒谎）；
* `ops-val` 里**不许出现数字**；
* 同步失败率必须写明"**按设计有意不上报**" —— 这是事实，不是缺数据（发它就是编数据，见 `docs/feature-backlog.md` 第五节）。

四条断言里的每一条，都对应一个真实的坑：这四格曾经被渲染成一排 `0`，
看上去像"指标很差"，而不是"还没有后端"。

每条指标都写清了 `requires`（要哪个埋点事件）与 `needs`（还差什么非代码的东西），
所以**接上后端的那一刻，这四格会自己亮起来，不需要回来改这一页**。

`docs/analytics.md` 的第四、五屏（留存/变现、健康度）也大多是这种"要先有后端"的指标；
工作台把"算不出来的"如实标成 ⊘，而不是画一条假的平线。

## 四、它不做什么（写明白，免得被当成万能）

* **不是线上监控**：没有服务端、没有告警、没有历史曲线（历史要时序库，一期没有）。
* **不是 CI 面板**：CI 跑的是 `./verify.sh` 本身（`tool/check-ci.mjs` 钉着"CI 绿 = 门禁绿"），
  工作台只是**本地**再跑一次给你看。
* **不替代六层门禁**：它跑的那 13 个快守卫是门禁第 2 层的一个子集，
  真正的发布判据永远是 `./verify.sh` 全绿。
* **不写任何文件**（除了 `--out` 你指定的那个 HTML）：门禁日志只在内存里，不落盘。
* **不引任何 npm 依赖**：数据层与渲染层只用 `node:` 内置模块，clone 下来直接能跑。

## 五、代码在哪（数据层已经从页面里拆出来了）

2026-10-04 把解析逻辑从 `tool/workbench.mjs` 里抽成三份**公共零件** —— 原因是这三处以前
各自复制过一份，而"工作台自己解析错了"是这一页最危险的失败模式：它不会报错，
只会安静地把看板变成一片"没有条目"。

| 零件 | 管什么 | 自检是什么 |
|---|---|---|
| `tool/lib/markdown-table.mjs` | Markdown 表格切行/切节/去记号（转义竖线 `\|`、围栏代码块、退化行） | 16 条，含"拿真仓库的 `ROADMAP.md` 读一次" |
| `tool/lib/collect-docs.mjs` | 5 份文档 → 同一形状（路线图 / 待办 / 上架清单 / 功能待办 / 决策索引） | 30 条，含"真仓库五份全读得出" |
| `tool/lib/collect-repo.mjs` | 版本 / CHANGELOG / `dist/` 残留 / git 状态 / 证据 / 合规开关 | 19 条，含"真仓库全读得出" |

三份都在 `verify.sh` 里各有一条 `selfcheck`，**都拿真仓库跑一遍**（不是只喂夹具）——
所以"路径拼错了导致全部读空"这种事当场就露。`tool/workbench.mjs` 自己的自检是 42 条。

## 六、踩过的坑（都变成了自检）

| 坑 | 症状 | 现在钉着 |
|---|---|---|
| 守卫路径漏了 `tool/` | 13 个守卫**全部**报红，报的是一句没头没脑的 `Node.js v22.22.2`（node 找不到模块时的最后一行） | 自检里有一条**在真仓库上跑一次真守卫**：路径拼错 / node 起不来 / 工具被改名，都会红 |
| iOS 设备解析按表格切列 | `devicectl` 的表里 Hostname 常常是空的，空列被吃掉后 `connected` 读错位置 → **连着的 iPhone 被算成 0 台** | 改用 `--json-output`，解析抽成 `parseIosJson()` 并由自检喂假 JSON 钉住（顺带钉住机型字段在 `hardwareProperties.marketingName`，取错会渲染成一段空白） |
| **裸的 markdown 记号漏进页面** | 页面上真印出星号（"下面这些数`**`不代表任何真实用户`**`"）。`Text` / HTML **都不渲染 markdown**，写了 `**` 用户就真的看到星号 —— 这条规矩本来就是从 App 那边学来的（`tool/check-user-text.mjs` 第一条） | 硬断言：**渲染出的 HTML 里不许出现裸 `**`**。而且失败时会把"在第几字节、上下文是什么"直接打出来 —— 因为它是全局断言（任何来源都拦），只说一句"页面里有 `**`"的话，就得去翻几十 KB 的 HTML 才能定位 |
| **组名里的 `**` 被写进了键名** | 文档标题本身就带加粗（`ROADMAP.md` 的「（`**`最划算`**`）」、`release-checklist.md` 的「政策`**`必须`**`同步改写」），而组名会被拼进 `data-group` 和 localStorage 的键前缀 —— 不归一化就两头都错 | 文档来的标题/正文渲染前一律过 `plain()`；另加一条断言：`data-group` / `data-ck` 的值里不许出现 `**` |
| 业务指标被渲染成一排 `0` | 看着像"指标很差"，不像"还没有后端" —— 一个会撒谎的看板 | 四条断言（全部 `⊘ 待接入` / 不许 `%` / `ops-val` 不许有数字 / 必须写明"按设计有意不上报"） |
| 空数据时还在说"这些数不代表真实用户" | 那时**根本没有数**，这句话本身就是在暗示有数 | 断言：空状态必须说"还没有数据"，且不许出现"不代表任何真实用户" |

共同的教训写在这里：**"全部失败"要么是真塌了，要么是工作台自己错了** ——
一页现状如果自己会撒谎，它比没有这一页更耽误事。
