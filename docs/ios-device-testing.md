# 没上架 iOS 之前，怎么在**真 iPhone** 上测（方案）

> 2026-10-01 出方案。**没有 Apple Developer 付费账号、也没上传 App Store** 的前提下，
> 想在真 iPhone 上跑我们的 App —— 这篇把三条路讲清楚、给出可执行的步骤、
> 指出**哪几件事只有真机能回答**，以及我这边能自动化到什么程度。
>
> 现状（已到位的东西）：Xcode 27.0 已装、模拟器运行时 iOS 27.0 已装、
> `flutter build ios --release --no-codesign` 能编出 20.7MB 的 arm64 包、
> 商店截图已能在模拟器出图（`store-assets/screenshots-ios/`，14 张）。
> **差的就是"装到真机上"这一步，而那一步需要签名。**

## 一、三条路

| 路 | 要什么 | 有效期 | 能干什么 | 不能干什么 |
|---|---|---|---|---|
| **A. 免费 Apple ID（Personal Team）** | 一个 Apple ID（不需要付款） | **签名 7 天**，过期后 App 打不开，重新装一次即可 | 在自己**那台** iPhone 上跑真机包；把"只有真机能回答的问题"全部验掉 | 不能 TestFlight、不能 Ad Hoc 分发、不能给别人装 |
| **B. 付费开发者账号（¥688/年）+ TestFlight** | 付费账号（个人或公司主体） | 构建 90 天；内部测试 100 人 | 上架前的**正路**：真机、多设备、可回滚、给测试者发邀请 | 仍然不是"上架"；仍要过 App Store Connect 的表单 |
| **C. 模拟器 + 安卓真机（**现在的状态**）** | 无 | — | 布局/流程/截图/两端一致性 | 手感、性能、后台策略、系统集成 —— **真机特有的一律测不到** |

**我的建议**：**先走 A**（今天就能开始，不花钱），把"只有真机能回答"的清单验掉；
等你决定上架时再走 B（B 的每一步我都已经准备好，见 `docs/release-admin.md`）。

## 二、A 路：免费 Apple ID 的完整步骤

> ⚠️ 下面带「口径」标记的数字是社区/文档常见说法，Apple 没在单一页面写全。
> **第一次跑的时候我会把实测结果写回这份文档**（这是本仓库的规矩：不确定的标出来，不自称确定）。

1. **在 Xcode 里登录 Apple ID**（免费即可）：`Xcode → Settings → Accounts → +`。
2. **打开工程**：`app/ios/Runner.xcworkspace`
   （我们是 **SPM 路线**，没有 `Podfile`；`Runner.xcworkspace` 里只有 `Runner.xcodeproj`）。
3. **选 Runner target → Signing & Capabilities**：
   * 勾上 *Automatically manage signing*；
   * **Team** 选 `你的名字 (Personal Team)`；
   * **Bundle Identifier** 改成**你自己唯一的**一个，例如 `com.<你的名字>.lianleme.dev`。
     > ⚠️ **这一步会让我们的守卫判红**：`tool/check-ios-app.mjs` 要求
     > 「产物里的 bundle id == 源码 Info.plist == 安卓 applicationId」三处一致 ——
     > 那是**故意**的（防止两头漂）。用它做真机测试时请把这条当成"临时 dev 包"，
     > 测完改回来；或者我给你在文档里记一条"dev 签名例外"（见第六节）。
4. **iPhone 上开两个开关**：
   * `设置 → 隐私与安全性 → 开发者模式` → 打开（**iOS 16 起必须**，会要求重启）；
   * 首次安装后：`设置 → 通用 → VPN 与设备管理` → 信任你的开发者证书。
5. **装上去**：
   ```bash
   # 用 Flutter 自己编 + 签名（会自动用工程里的 Team）
   cd app && flutter run -d <你的 iPhone 的 device id> --release
   # 或者：Xcode 里选中你的 iPhone，⌘R
   ```
   查看设备 id：`flutter devices` / `xcrun devicectl list devices`。
6. **7 天后**：App 会打不开（签名过期）。**重跑第 5 步**即可（数据不会丢 —— 我们的数据在
   App 沙盒里，重装同一个 bundle id 覆盖安装会保留）。
   * 我这边可以写一条一键脚本（暂定名 `ios-device.sh`，**还没落地** —— 按本仓库的规矩，
     没跑通过的脚本不写进文档当成品）：编包 → 装 → 拉起 → 抓 30 秒日志；到期重签就是再跑一次。

**A 路的已知坑（我们会踩到的）**

| 坑 | 症状 | 处理 |
|---|---|---|
| 免费档的 App ID / 设备数量上限（口径：**每 7 天 10 个 App ID**） | Xcode 报 "reached the maximum number of App IDs" | 别反复改 bundle id；用固定的那个 |
| 同一台设备上免费签名 App 的数量上限（口径：**3 个**） | 装第 4 个时失败 | 删掉不用的自签 App |
| 首次安装要"信任证书" | 点开 App 直接闪退 | 见上面第 4 步 |
| `flutter run` 默认是 debug 包（JIT） | 性能不是真机性能 | 验性能要用 `--release`（然后就不能热重载了） |
| 模拟器与真机的相册/分享行为不同 | "存相册"两条权限路在真机上是另一套 | 我们在模拟器上验过逻辑（`share_card_gallery_test.dart`），真机上要重走一遍 |

## 三、B 路（付费账号）在这里的位置

付费账号解决的是 **"给多台设备 / 给测试者"**，不是"能不能装到真机"（那是 A 路就能做的）。
等到以下任一条成立时，就该上 B：

* 你要把包发给**别人**（家人/朋友/测试者）→ TestFlight；
* 你要**上架**（`docs/release-checklist.md` 的终局核验全绿之后）；
* 你要做"内部测试 90 天可回滚"的正式流程。

B 路的材料已经就绪：出口合规口径（`docs/store-listing-ios.md`「出口合规」）、
App Privacy 标签、审核备注、14 张截图、`docs/release-admin.md` 的差异清单。

## 四、**哪些问题只有真机（iOS）能回答** —— 这才是走 A 路的理由

| # | 问题 | 模拟器能不能答 | 真机怎么验 | 我们打算怎么判 |
|---|---|---|---|---|
| 1 | 训练屏大按钮的**手感**（出汗、单手、站着） | ❌ | 你自己用手指走一遍 | 只有你能判（`docs/your-todo.md` §④） |
| 2 | **性能**：60fps 列表、冷启动、动画掉帧 | 🟡 模拟器不代表真机 | 真机 + Instruments / `flutter run --profile` | 冷启动 < 1.5s、列表滚动无卡顿 |
| 3 | **后台/网络切换**：云备份在弱网、切网、后台被挂起时的行为 | ❌（模拟器不模拟 Doze） | 真机装 v1.34.0 + 配了地址的包，放兜里过一天 | 断网重试、恢复后补传 |
| 4 | **相册权限**：只有「仅新增」权限时，真机弹什么、被拒后什么表现 | 🟡 逻辑可测，弹层文案真机才知道 | 真机走两条权限路 | 与模拟器结论是否一致 |
| 5 | **分享面板**：系统分享面板里我们的卡片长什么样 | ❌（系统 UI，自动化点不到） | 真机手动看 | 只有你能判 |
| 6 | 启动屏**毫秒级白闪** | ❌ | 真机录屏逐帧看 | 仍未证明（`docs/release-admin.md`） |
| 7 | 系统字体放大 / 深色模式下真机渲染差异 | 🟡 | 真机 `设置 → 显示` 调一遍 | 与截图矩阵对账 |

**结论**：A 路能一次把这些里的 2/3/4/7 验掉；1/5/6 需要你的手指和眼睛 ——
这也是为什么"真机走查"那条待办一直挂在 `docs/your-todo.md` 里没有被自动化顶掉。
