## 二、验收（当场过一遍；勾不上就是缺陷，记下来）

### 基础通路

- [ ] 手机上出现 App，点「开始今天的训练」进到训练屏
- [ ] 「我自己选」能搜（试 `bp`、`rdl`），点一个动作进训练屏，点大按钮记一组
- [ ] **练两个动作**（卧推 → 返回 → 深蹲），两组都在
- [ ] **杀掉 App 重开** —— 组一条不少
- [ ] 重开后进同一动作，能看到「上次 xx kg × n」

### 渐进建议真的接上了

- [ ] **第二次训练同一个动作**时，训练屏大按钮上的重量 = **建议卡上那个数**
      （不是动作库默认值 40kg），且理由文案不是"第一次练这个动作"
- [ ] 隔 21 天以上再练同一个动作，看到的是「已经有 N 天没练，先按上次重量找回感觉」

### `tap_count`（唯一的客观指标）

- [ ] 第一次训练的第一组 = **2**（首页大按钮 → 训练屏大按钮），不是 1
- [ ] 修掉大按钮重量之后，第二次起的每组**不再需要**"长按 + 两次步进 + 确定"那 4 下

## 三、把这趟的数字交回去（**这一趟唯一能产出的客观数据**）

以前没有这一步：没配上报地址的包里 `_NullTransport` 恒失败，事件只落在本地队列，
**没有任何出口** —— 于是练完只能得到"顺不顺"的印象，`tap_count` 一个数都拿不到。
现在有了：

```
手机：「我 → 隐私与关于 → 导出统计事件」（开关得是**练之前**就打开的那个）
      → 系统分享面板 → 发给自己（微信 / 邮件 / 小米互传都行）
电脑：把文件存成  server/data/events-YYYY-MM-DD.jsonl
      node tool/analytics-report.mjs          # 北极星漏斗 + tap_count 中位数/P90
```

> 2026-10-04 已在真机（Redmi `flourite` / v1.37.0）上把这条路径走过一遍：
> 开关关着 → 入口不出现；打开 → 入口出现 → 点它 → 系统分享面板收到
> `练了么-埋点-2026-10-….jsonl`（2.30 KB）。证据图 `docs/images/a0-04` / `a0-05` / `a0-07`。
> **文件在应用私有 cache 里（Android 11+ 用 adb 取不到）**，只能走分享面板 —— 所以这一趟必须你手动发一次。

要看的三个数（`docs/analytics.md` §3、§7）：

| 数字 | 在哪 | 怎么读 |
|---|---|---|
| **`set_logged.tap_count` 中位数** | 报告里 | **硬约束 = 1**（同一动作第 2 组起）。第一次是 2 属正常 |
| `tap_count` 的 **P90** | 报告里 | 看尾巴：偶发的高值比中位数更能暴露"某一步很烦" |
| 漏斗四环 | 报告里 | `app_open → workout_started → set_logged → workout_finished` |

> 导出**不做任何清理**（不删队列、不改开关），所以随时可以再导一次。
> 那一趟的真实数据值得留档：把它贴进 `docs/analytics.md` 的实测区，
> 与阶段 5 的 5 人测试数字**分开记**（一个是"开发者自己在健身房"，一个是"5 个真人"）。
